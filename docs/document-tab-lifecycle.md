# 文档标签生命周期边界

`useDocumentTabs` 是 `useDocumentSession` 的稳定门面；调用方仍通过同一套 API
创建、读取、切换、关闭、固定和重排标签，不直接依赖内部模块。

核对日期：2026-09-22，当前实现说明。已覆盖的保存会话身份保护不能推导为所有异步旁路都已隔离；来源登记另有 P1-06 待办，详见[领域模型](domain-model.md)和[代码审阅](development/reviews/2026-09-22-code-function-review.md)。

实现按副作用边界拆分：

- `useDocumentTabOpening`：新建、样例文件、系统打开对话框和工作区文件读取；它保留
  慢磁盘请求去重与“较晚读取不抢焦点”的选择意图规则。
- `useDocumentTabClosing`：预览回收、关闭前保存、草稿与自动保存清理、窗口关闭保存、
  固定和重排。
- `useWorkspaceDocumentView`：只持久化和恢复工作区内文件的选区/滚动状态；未命名和
  工作区外文件不写入工作区文档状态。上次搜索词和最近引用路径在工作区设置里，不在这里，也不含正文。
- `tab-close-plan`：关闭后的剩余标签和活动文档选择是纯函数，并由单元测试固定。

跨模块协调仍集中在入口：切换标签、新建、打开和重命名/删除/移动前，大文档若仍有未落账输入会先等待 listener
快照；超时则取消操作并保留当前编辑器，避免 `replaceEditorContent` 冲掉末次按键。
打开对话框和样例文件在等待之后用当前 `openFilesRef` 判断是否已打开，避免对话期间从树里打开同一文件造成重复标签。
活动预览仍有未落账输入或缓存未对齐时会固定而不是拆掉。编辑器内容回到已保存基线时也会消耗 pending dirty，避免 leave/close 空等超时。
重启恢复草稿时，若草稿记下了起草时正文的哈希，磁盘正文已经不同就放弃草稿，不以修改时间判断。
普通文档或已落账快照立即落账旧内容、失焦标题、同步活动 ref，再替换编辑器内容
并恢复目标视图。这样 ProseMirror/Milkdown 仍是正文唯一状态源，不会因拆分产生
第二份可编辑正文状态。

关闭前的保存逻辑位于 `useDocumentCloseSaving`。每次发起关闭都冻结目标文件路径、
活动会话序号和编辑器实例；每一次异步等待（快照、另存为、队列写入、确认弹窗）后
都重新检查这三个条件与最新正文。超时、切换标签或工作区、路径迁移、组件卸载、
保存期间继续输入，都会保留 dirty 并拒绝关闭；它不会把旧缓存冲刷到磁盘，也不会把
另一篇文档的编辑器状态当作该标签已经落账。窗口级关闭在所有标签确认之后再复核队列
和工作区视图写入期间有没有新输入或新标签。保存请求携带该标签自己读取/确认过的
`expectedMtime` 与 `expectedContentHash`；主进程比较磁盘字节哈希，不用 500ms mtime
容差或另一窗口更新过的进程全局基线放行旧版本。forceOverwrite 取消时标签保持 dirty。

手动另存为同样绑定发起时的文件路径、活动会话和编辑器实例。系统保存对话框返回时若
目标已切换或组件已卸载，已写出的文件不会覆盖当前标签、修改会话状态或在卸载后更新界面；
仍在运行的会话会提示用户该结果没有套用到当前文档。

## 待补充的来源生命周期

P1-06 将登记请求绑定工作区 epoch/记录版本，清除、卸载与 A → B → A 切换使旧回包失效；P1-07 将来源关系绑定引用文档，覆盖未保存身份、另存为、改名/移动、撤销/重做与保存重开。这些目前是验收目标，不能以标签保存测试已经通过推断实现完成。所有新增关系状态仍是正文派生元数据，不成为第二份正文状态。
