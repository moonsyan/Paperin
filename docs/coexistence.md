# 和现有 Markdown 工具共存

Paperin 打开的是普通文件夹里的 Markdown，不要求迁成私有格式。正常试开不主动格式化正文；用户保存会写文件，读取到中断保存 journal 时也可能触发授权范围内的恢复，见[恢复协议](file-write-recovery.md)。

## Typora 和 Obsidian

- 继续用原来的文件夹。Paperin 和它们可以先后打开同一篇 `.md`。Paperin 保存时校验外部修改并报告冲突；其他工具的冲突策略由其自身决定，不能保证任意工具最后保存都受 Paperin 保护。
- 从这些工具复制 Markdown 原文贴进 Paperin 时，按标题、列表和强调排版，不会因为剪贴板里的 HTML 包装变成纯文本。
- 图片请用相对路径。打开后如果提示附件找不到，先看图片是不是还在库里，不要让任何工具自动改写正文。
- `[[双链]]`、标题和普通链接会按能解析的部分显示。解析不了的原文保留，并在打开检查里说明。
- 在 Paperin 里用工作区搜索找到旧资料后，「插入引用」写入的是当时的文本快照加指向原文件的链接，不会改来源文件。保存后换一篇再打开，引用仍在当前草稿里。质量面板会按插入时的修改时间提示来源变化或缺失；文件被移走后需要自己重新定位，不会自动改正文。
- 工作区状态写在库目录的 `.paperin` 里，和正文分开。删掉它不会删除笔记，但会丢失布局、阅读位置、来源记录和发布配置；共享目录或 Git 应明确排除这些私有状态。

当前来源时间记录由工作区共用，重复引用会更新共享基线；逐篇跟踪、显式复核和关系迁移尚待实现。外部改名或增删附件后的诊断更新仍有待补边界，不能凭没有提示判为已完整核验。

## Notion、语雀、思源

这些工具的专有块、数据库和嵌入不能当成无损迁移。请先用它们自己的 Markdown 导出，再把导出副本交给 Paperin 打开。

- 只检查副本，不回写到来源账号或原库。
- 导出里缺掉的图片、断掉的链接和不完整的脚注会在打开时说明，原文段落不会被删掉或自动改写。
- 对不上的语法按普通文本留下。Paperin 不承诺还原数据库、同步块或私有嵌入。

兼容夹具任务 P1-02 尚未完成五类真实导出验证；工具名称仅表示计划检查范围。正式验证须记录来源版本/导出方法，合成示例不得冒充真实兼容；正常无恢复记录的试开前后比较 Markdown 与附件 hash，`.paperin` 元数据单列。当前证据见[兼容矩阵](compatibility-matrix.md)。
