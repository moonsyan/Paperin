# LastFileHome 下一版：柔和工作台与个人知识复用

日期：2026-09-13。审查起点：`58901d6`，`package.json` 版本 `0.6.0`，开始时工作区干净。

本次交付包含**产品评估、设计原型和生产壳层视觉迁移**，没有接入模型或启用发布服务。实际实现进度仍以 [REFACTOR-STATUS](REFACTOR-STATUS.md) 为准。原型位于 [design/soft-workbench](../design/soft-workbench/README.md)，生产视觉层位于 [soft-workbench.css](../src/renderer/src/styles/soft-workbench.css)。

生产迁移只覆盖布局、间距、颜色层级和响应式呈现：继续使用现有 Sidebar、TabBar、Milkdown Editor、DocumentPathbar、ContextDock、StatusBar 及其状态/事件契约。默认主题现在采用原型的雾白基线；用户已经选择的 mist、pine、dark 等主题仍保持各自 token。侧栏展开时，顶栏左侧按“收起按钮 → Logo → MarkdownSoft”排列；收起侧栏后 Logo 与项目名同步隐藏，只保留按钮作为重新展开入口。侧栏内部不重复渲染品牌。顶栏的低频菜单收敛为完整可读的“更多…”入口，先展示常用命令，再按文件/编辑/段落/视图/帮助分类，并支持命令搜索；菜单项、快捷键与命令分发保持不变。当前文件来源/保存状态继续保留在无障碍树、路径条和状态栏。文件读写、保存冲突、搜索、历史、导出、主题切换和快捷键没有迁移到原型的演示状态，也没有新增平行数据源。

## 1. 已确认的产品意图

以本轮最后一次回复为准：

- 面向个人用户，兼容知识积累、写作和项目资料管理。
- 同时希望安静、清晰高效、有知识关联，但默认页面必须简洁、柔和、有重点。
- 当前持续免费，优先本地体验和 AI 辅助资料复用。
- 暂不推进跨设备同步；发布仍是未来方向。
- 曾提出收费意愿，之后明确“先暂时一直免费”。因此本计划不设置收费版本、付费墙、订阅或强制账户，未来商业化另行验证。

三个场景可以兼容，但不能把三套产品的全部入口放在同一页。**统一的数据与导航、按任务展开的工具**是兼容的前提。

## 2. 建议定位：个人知识的本地工作台

建议对外描述：

> 把资料留在自己手里，把笔记变成下一次写作与行动的起点。

产品品类：本地优先的个人知识工作台。体验入口：好写、好找；长期价值：知识能够再次使用。

品牌名 LastFileHome 与“文件有归处”的方向契合。原型使用现有图标与新项目名称，不变更生产安装包、配置目录或应用标识。中文副标题可用“个人知识工作台”，不急于额外创造第二个品牌。

### 核心人群与待验证假设

| 人群 | 真实任务 | 首轮要解决的困难 | 当前优先级 |
| --- | --- | --- | --- |
| 经常阅读、写作的个人用户 | 找回旧笔记，完成新文章 | 存过但找不到、找到了用不上 | 主验证人群 |
| 有个人项目的知识工作者 | 整理参考资料、决策与行动 | 项目资料散落，任务与背景脱节 | 同一闭环的延伸 |
| 重度知识管理爱好者 | 建立复杂关联体系 | 希望更细粒度的组织能力 | 兼容基础需求，暂不追求所有高级玩法 |

这些是招募用户的假设，不是市场调查结论。首轮建议找 5–8 位存在真实资料复用任务的人试用，而不是只问“截图好不好看”。

### 核心闭环

```text
收下资料 → 写出理解 → 找到相关内容 → 用进文章或项目 → 导出成果
                       ↑                              │
                       └──────── 下次继续使用 ─────────┘
```

写作、知识积累与项目管理是这一过程中的不同任务。项目初期就是一个文件夹、一篇项目概览、相关笔记与 Markdown 任务列表；不因此引入数据库、看板、工时、成员权限等第二套系统。

## 3. 现有项目的真实基础与问题

证据类别：**代码确认**指静态调用链；**本轮实测**指本次执行；**历史实测**指有日期的既有记录；**产品假设**仍需试用。

### 可继续利用的基础

| 领域 | 证据与判断 | 对下一版的意义 |
| --- | --- | --- |
| 技术栈 | Electron / React / strict TypeScript / Milkdown，见 package 与 [TECH-STACK](TECH-STACK.md) | 不需要为视觉重构换框架、重写编辑器 |
| 进程边界 | Main、Preload、Renderer、Shared；typed desktop API | AI、导出等后续能力仍可通过窄 API 接入 |

| 工作区能力 | 多标签、文件树、收藏、搜索、索引、链接、外部文件复用工作台 | 足以支持个人知识闭环的第一版，不缺另一个首页仪表盘 |
| 扩展边界 | CommandRegistry、PanelRegistry、ContextDock、reveal 视图模型 | 低频功能应接已有入口，无须在顶栏逐个新增按钮 |

这些是工程资产，不意味着每项都是竞品没有的功能，也不等于已形成市场壁垒。

### 为什么仍显繁杂

1. **同一上下文在不同层重复。** `AppTopBar` 仍同时装配品牌、菜单、工作区上下文、标签、fileContext、可编辑 doc-title、专注、主题和设置。`TopBarSlots` 继续注入 CurrentFileBanner；DocumentPathbar 又在正文上方呈现路径。库名去重已经实现，但全部重复尚未收口。
2. **高频与低频能力处于相近视觉层级。** 主题快切、设置、文档操作、知识辅助共同占用注意力。用户需要先识别工具，再进入内容。
3. **“完成了某个组件”不等于布局整体已收敛。** 既有 M2 任务已有大量实现，但状态文档同时存在“全部完成”与较早的“进行中/仍需收敛”叙述。需要用一份验收清单判断整体结果，避免再次根据旧标题重做已完成任务。
4. **轻量化不只涉及颜色。** 低对比小文字、过多元信息、不同入口的状态差异，都会让柔和主题仍难以理解。降低信息数量要优先于把文字继续调淡。

## 4. 如何借鉴主流产品，又保留自己的风格

| 参考 | 已核对的方向 | 适合借鉴的交互原则 | LastFileHome 的取舍 |
| --- | --- | --- | --- |
| Typora | 连续读写、减少预览切换干扰，也有文件管理和大纲 | 正文优先，写作工具按上下文出现 | 加强跨文档找回和复用，不把它误解成只有单文件 |
| Obsidian | 本地知识管理、内部链接、反向链接 | 文件可掌握，相关笔记可跳回来源 | 默认呈现小范围、有用的关联；全局图谱留在次级入口 |
| 思源 | 本地、块级引用、双链和加密同步等 | 用聚焦和折叠管理复杂度 | 当前继续以 Markdown 文件为边界，不为了“像思源”迁移块存储 |
| Notion | 侧栏组织工作区内容 | 导航与内容层次清楚，页面易浏览 | 不把数据库、协作与账户体系设成个人写作的前置条件 |
| 语雀 | 面向个人和团队的知识组织与分享 | 项目/知识库目录清楚，输出可阅读 | 先做本地成果导出，在线发布独立验证 |

来源核查于 2026-09-12/13：[Typora 官方](https://typora.io/)、[Obsidian 官方](https://obsidian.md/)、[反链帮助](https://obsidian.md/help/plugins/backlinks)、[思源官方](https://b3log.org/siyuan/)、[Notion 侧栏说明](https://www.notion.com/en-gb/help/navigate-with-the-sidebar)、[语雀官方组织](https://github.com/yuque)。语雀主页未提供可读取正文，未据此声称评估过其全部当前 UI。上表的取舍是设计判断，不是竞品优劣排名。

“torrioria”暂按 Typora 理解；若指另一产品，后续只需替换该参考，不影响当前原型主线。

**差异化应由一整套体验验证：** 开箱可用的中文读写、清楚可信的本地状态、无需布置系统就能复用资料、AI 建议可以核对来源。绿调、留白、本地文件、双链或 AI 中的任一项单独存在，都不足以证明差异化。

## 5. 界面方案：静下来，才看得到重点

本版是对已有留白方向的进一步减法。视觉参数：变化度 5/10、动效 2/10、密度 3/10。延续项目雾白/松绿家族，采用原生 CSS 与已有 React，不引入新的 UI 框架、远程字体或营销页模块。

UI/UX 技能设计系统检索返回了叙事落地页、棕紫配色，和桌面知识库不匹配，未采用；定向 UX 检索只采用可确认适用的键盘、焦点与导航建议。桌面尺寸与色值由项目现有主题和原型检查确定。

### 默认布局

```text
┌ 我的知识库导航 ┬ 当前文档标签                  专注  辅助  更多 ┐
│ 搜索          │ 相对路径                                  编辑 │
│ 最近 / 收藏   │                                                │
│ 全部笔记      │     正文标题                                   │
│   随笔        │     真实文档内容                               │
│   项目        │                                                │
│   阅读        │     关联入口放在阅读结束处                     │
│ 外观与说明    ├ 保存状态                             简单统计 ┤
└───────────────┴────────────────────────────────────────────────┘
```

- **安静写作**：默认两栏，正文为重点；不默认展开右侧面板，不默认放 AI 输入框。
- **高效找回**：侧栏搜索始终可点击，快速打开支持键盘，结果打开后仍保留写作上下文。
- **知识探索**：点击“辅助”或文末关联，右侧才出现大纲 / 关联 / AI；一次只显示一种辅助内容。
- **个人项目**：沿用同一文件导航与编辑区。原型中的“九月阅读计划”“个人主页改版”展示资料、行动和成果目标如何共存。
- **专注**：临时隐藏两侧，退出后恢复原面板；不是第二套应用模式，不迁移文件和正文状态。

### 视觉识别

| 元素 | 原型初值 | 用途 |
| --- | --- | --- |
| 背景 | `#FCFCF9` | 轻微柔和，保持正文对比度 |
| 侧栏 | `#F0F2ED` | 导航自然后退 |
| 主文字 / 次文字 | `#29372F` / `#5C695F` | 通过深浅与字号区分信息，避免极淡灰 |
| 强调色 | `#3C7154` | 只用于选择、链接、焦点和引用 |
| 选中行 | `#E0EADF` + 3px 左标记 | 颜色之外仍有明确形状提示 |
| 正文 | 15px / 2.05 行高，内容宽约 688px | 中文长段落阅读的原型起点；生产迁移尊重用户排版设置 |
| 顶栏 / 路径 / 状态 | 60 / 39 / 30px | 原型尺寸；生产目标仍需结合现有 52px 顶栏与系统标题栏测试 |
| 圆角 | 行与按钮 6px，弹窗 12px | 层级一致，避免大量卡片与胶囊 |

“归处”的视觉线索来自同一条细绿标记：活动文件、文档页边、引用内容。它们对应定位或内容层级，不在每个列表项前加装饰点。短句“文件在手边，想法有归处”仅保留在侧栏底部，不反复出现。

### 现有能力放到哪里

| 能力 | 主入口 | 要保留的约束 |
| --- | --- | --- |
| 打开、新建、搜索 | 侧栏、应用菜单、快速打开 | 无知识库也可打开外部文件 |
| 保存 / 另存为 | 快捷键与应用菜单；失败时就地操作 | expectedMtime、取消、冲突、编码损失分支完整 |
| 重命名、移动、回收站 | 标签/文件树上下文菜单、更多 | 文件名与正文 H1 不自动互相修改 |
| 主题、字号、宽度 | 外观设置 | 不占常驻顶栏，沿用设置 store |
| 大纲、反链、标签、属性、检查 | ContextDock 及现有面板入口 | 不删除现有面板或新建平行状态 |
| 全局图谱、历史、导出 | 更多、应用菜单、命令搜索 | 可发现的文字入口，不能只能记快捷键 |
| AI | 辅助面板、选区动作（未来） | 可关闭，范围明确，来源可核对 |
| 发布 | 文档操作（未来） | 发布前预览范围与资源，错误不影响正文 |

原型使用可点击搜索和现有默认 `Ctrl+P`；没有注册生产新命令。生产提示继续从快捷键配置生成，不把原型的固定文案复制进应用。原型不截获 F11，避免与浏览器全屏冲突。

### 正式迁移必测状态

无库、空库、有库无文件、收藏为空、无搜索结果、外部文件、同名文件、20 标签溢出、长中文目录、dirty、正在保存、保存失败、冲突、编码损失、取消、抽屉 Escape/焦点恢复、中文输入法组合态、820px 两侧互斥、100%/125%/150% 缩放。

未保存标记允许必要冗余：标签、关闭确认与窗口状态都要呈现。不能为了极简只保留底部一处 dirty。没有 H1 的文件照常打开，壳层不得伪造并写入标题。

## 6. AI：先帮助用好资料

用户已明确它是优先发展方向。建议在可靠本地壳层之后立即做一个窄而完整的 AI 试验，而不是把 AI 无限延期，也不同时建设聊天、代理、自动分类、语义图谱和自动发布。

**首个实验：从用户指定的 1–5 篇笔记中回答问题，附可点击来源，并把建议以预览方式插入当前文档。**

1. 范围显式选择：当前文档、选中的几篇、以后再扩展指定文件夹。
2. 最初复用已有标题/正文检索；只有真实问答样本证明召回不足时，再比较分段索引、中文词法与向量方案。
3. 回答和来源分开展示；标出没有依据的推测。引用绑定文档与段落/版本，源文件改变时提示重新核对。
4. 替换文字先展示差异，用户决定应用；应用只走编辑器事务，可以撤销。
5. 请求可以取消，切换文件后迟到响应不能写入新文档；同一操作防重入，失败保留问题与选择范围。

### 本地隐私与免费如何共存

- “本地优先”不等于“连接云模型也不会发送文本”。默认不启用远程发送；启用前显示提供商、所选内容范围和发送行为。
- 免费桌面应用不等于无限免费推理。首轮可以选自带模型服务或本地模型适配中的一种先验证；第三方使用费用和设备要求应在配置时说明，不能许诺由项目长期承担无限调用。
- 密钥由 Main 使用系统安全存储能力管理；不放正文、Renderer 持久化、导出或普通日志。模型结果按不可信内容处理。
- 资料中的指令不能授予模型读其他文件、执行命令、删除、联网或发布的权限。第一版不提供自主文件操作工具。
- 日志只记录必要的请求状态与耗时，默认不记录问题、正文和绝对路径。诊断资料由用户选择导出。
- 无模型时，本地编辑、查找、关联、导出仍完整可用。

以上是实现约束，尚未接入任何提供商，不把概念预览计为 AI 功能完成。

### AI 的验收而非宣传指标

建立 30 个可公开或合成的中文任务：事实查找、跨笔记对照、材料不足、相互矛盾、陈旧引用、恶意文档指令。逐条检查来源是否支持结论、是否擅自补事实、是否能取消和撤销。记录找资料/写作时间及真正采用的建议；不以“生成字数”证明价值。

## 7. 发布、同步与长期边界

**发布先从已存在的导出体验开始。** 优先验证图片相对路径、中文字体、公式、表格、Mermaid、脚注、frontmatter、代码块在目标输出中的结果。下一步才做单篇文章发布预览、链接/附件检查与可撤回的发布记录。全站托管、域名、账户和访问统计要有真实需求后再投入。

**同步暂停实施。** 当前不加登录同步按钮、不建设服务器、不把它作为使用知识库的条件。架构上继续保持正文、应用状态、索引分离；不要在尚未验证的阶段承诺冲突自动合并或移动端全功能。

**关联先服务当前任务。** 优先来源清楚的反链、出链、相关段落与回跳位置。全局图谱可以保留，但不作为默认首页或衡量知识积累的成绩单。

**免费阶段的可持续性。** 控制服务成本，公开支持范围和版本变更；反馈、赞助或未来专业服务是可讨论选项。收费、开源策略与许可证调整都不在本次执行范围，也不影响用户取回原始 Markdown。

## 8. 技术重构路线：保留核心，收敛壳层

### 建议职责与迁移关系

| 原型表达 | 生产接入位置 | 实施注意 |
| --- | --- | --- |
| Workbench 布局 | WorkspaceShell / AppComposition | 拆分装配，不迁入原型 sampleNotes 状态 |
| Navigation | Sidebar 与已有文件/收藏/最近数据 | 同名、外部来源、折叠和持久化语义保留 |
| NoteContent | Editor + DocumentPathbar | 原型文本排版器与 textarea 不能替代 Milkdown |
| Inspector | ContextDock / PanelRegistry | 原型三页是体验示例，不能因此删除其他面板 |
| 搜索 Dialog | 快速打开、命令注册、工作区搜索 | 使用现有算法与 reveal，保留取消及最后选择获胜 |
| AI 建议 | 新增 Main 服务 + typed Preload + Shared DTO + 面板 | scope、取消、错误、密钥与来源都需明确建模 |
| 外观 token | styles 语义变量及九主题映射 | 两套原型颜色不等于完成九主题迁移 |

### 推荐拆分优先级

1. AppComposition 按顶栏装配、文档区、overlay 编排拆开；不把业务状态再复制到新的外壳。
2. file-handlers 按保存与编码、路径变更、读取与生命周期拆分；安全校验使用公共现有边界。
3. useWorkspaceFiles 按操作协调与视图选择拆分；最新 ref 与取消契约保留。
4. useAppSettings 拆迁移、加载和主题/编辑外观适配；设置仍由 Main store 负责。
5. docx 按 AST 转换、样式和打包拆分；保持导出兼容矩阵和直接测试。

上述只描述下一阶段方向，本次不扩大到生产重构。拆分前先补边界测试；不要为了减少行数把复杂度转移到无语义 helper。

### 回退与数据兼容

先迁移一块 UI，再回归核心流程，再提交。视觉更改不写用户 Markdown，不改变 H1、不重命名目录。若改布局 schema，要提供缺省值、损坏回退和旧偏好迁移。回退版本只恢复代码/可兼容设置，不删除用户文件、草稿、历史或索引来源。

## 9. 从原型到下一版的执行顺序

以一位熟悉项目的开发者为估算前提，仅作排序与投入讨论，不承诺日期；重大性能问题和平台环境可能改变范围。既有 T01–T20 按最新状态复核，不重复安排已完成的 M0/M2 子任务。

| 增量 | 大致投入 | 本轮之后具体做什么 | 退出条件 |
| --- | --- | --- | --- |
| 设计试用 | 2–4 日 | 用原型走写作、找回、项目、关联四个任务；选择默认密度 | 用户能找到入口，知道文档位置与修改状态，记录具体反馈 |
| 可靠性收口 | 5–10 日起 | 继续 T06/T07 的保存/导出快照与大文件分段测量 | 即时输入后保存/关闭/导出与末次内容一致，超时明确可恢复 |
| 壳层迁移 | 5–8 日 | 复核 T09–T14 剩余差距，拆热点，减少顶栏重复，接已有抽屉 | 旧功能覆盖不减，所有主题/缩放/焦点与 IME 验收通过 |
| 资料复用试验 | 3–5 日 | 搜索回访、来源段落跳转、当前文档关联和项目模板样本 | 能完成“找回旧资料并用于新文章”任务 |
| AI 小闭环 | 5–10 日起 | 单一模型适配、显式范围、引用、取消、差异预览与撤销 | 合成任务可核对，无越权写入或静默发送 |
| 试用与发布验收 | 约 2 周试用窗口 | 收集 5–8 人任务反馈、修复问题、验证安装升级 | 可靠性与平台门禁过关，再确定发布范围 |

可靠性修复和设计试用可分别推进，但不在一个高风险提交里同时改保存协议和整个壳层。若资源不足，优先交付可靠本地壳层与小范围 AI 实验，不增加云同步和完整发布站点。

## 10. 用什么判断方向走对了

下列是首轮验收目标，不是已经达到的数据，也不是行业基准：

- 给参与者一个已有知识库，无提示完成“找到一条旧笔记并用到当前文档”；至少 4/5 人能完成。
- 打开界面后能回答“在哪个库、当前什么文件、修改是否保存”；不能仅凭界面清爽而忽略状态误解。
- 两周内观察至少 3 次真实资料复用任务，记录耗时、打断点、反复搜索和放弃原因。
- 记录 AI 引用错误、无依据结论、取消失败与错误文档写入；安全/数据错误必须为零才能扩大试用。
- 正常 Markdown 与中文输入不退步；大文件极端情况有明确边界，不用普通 smoke 替代性能证据。
- 数据默认留在用户设备。试用记录可由参与者手动提交，不自动上传笔记、查询或行为轨迹。

在稳定试用前，不用下载量、累计笔记数、图谱节点数或 AI 生成量判断产品价值。

## 11. 原型覆盖与边界

可操作：文件夹折叠、最近/收藏筛选、新建合成笔记、标签切换与键盘导航、中文搜索与无结果、演示正文编辑和会话内保留、收藏、专注、目录定位、关联跳转、AI 来源交互示意、明暗主题、窄窗互斥抽屉、弹窗焦点循环与 Escape。

未实现：真实文件读写、关闭标签/关闭确认、自动保存、生产编辑器完整 Markdown 语法、真实模型推理、同步、在线发布、多工作区切换和全部高级面板。原型没有假装保存到磁盘，也没有模拟成功的发布或 AI 调用。

原型首屏默认不显示复杂空白首页。无库/空库的正式方案继续使用现有 StartScreen 主动作规则，本次没有再造欢迎页面。原型主色和结构待用户视觉反馈，不直接覆盖 NEXT-UI-SPEC 的全部生产规范。
