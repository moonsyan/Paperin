## 1. 目标、优先级与执行门禁

交付结果：已有 Markdown 的中文作者，可以直接使用自己的目录，可靠保存，找回旧段落并带来源用进当前文章，稳定输出，再持续使用。

| 级别 | 意义 | 执行规则 |
| --- | --- | --- |
| P0 | 数据安全、保存/关闭、安全边界、发布阻塞 | 优先于一切增长功能；不能用产品评分或管理豁免跳过 |
| P1 | 核心复用、激活、可交付性与使用质量 | 对应阶段必须完成；依赖不满足先补基础 |
| P2 | 证据支持的增长、商业和效率增强 | 前置阶段达标再投；未达标回到核心任务 |
| P3 | AI、同步、团队、移动、插件生态等选项 | 达到战略进入条件后另行立项 |

严重度与排期区别：P0 代码风险不等于已经发生用户事故，但未查清前阻断相关承诺。真实丢失/静默覆盖按最高严重度响应，先保全与恢复，再修复和复测。

遵循 AGENTS.md：先写能失败的行为测试 → 最小实现 → 新边界直接测试 → 相关回归 → typecheck/test/build → 适用的 lint/a11y/smoke/性能/平台验证 → 同步文档 → diff/status → 独立提交。功能用 `feat:`，修复用 `fix:`，文档用 `docs:`，重构用 `chore:`。本次仅修订文档，没有产品功能改动。

超过 300 行评估拆分；超过 450 行先拆再加功能；组件超过 250 行或异步/状态门槛按职责拆分。不得新增第二套可修改正文源、通用 IPC、Renderer 文件访问或静默覆盖路径。新 DTO/IPC/错误码必须同步 Shared/Main/Preload/api.d.ts/Renderer/测试和维护说明。

## 4. G0：可信试用

### S00 / P0：冻结当前证据和失败基线

- 交付：按当前 commit 核对实际脚本、最近测试、CI run、安装与风险；在 REFACTOR-STATUS 顶部增加当前有效摘要，保留历史日期。梳理超限文件和测试缺口。
- 先验证：运行当前 smoke/perf:electron，记录失败阶段与磁盘一致性；检查 release.yml 的实际触发、门禁及产物范围。本轮文档任务未触发远端运行或发布。
- 验收：旧 T01–T21 全部有“已实现/缺验证/失败/待做”的映射；所有 P0 有负责人、复现或明确风险输入；不同 commit、模块性能、端到端性能不混用。协议 M01 的硬门禁不得放宽。
- 文档：REFACTOR-STATUS、compatibility-matrix、performance-baseline；证据只含合成样本摘要，不含用户路径/正文。

### S01 / P0：可恢复写入，同时保留文件身份需求

- 范围：`src/main/ipc/file-io.ts`、`file-handlers.ts`、save-lock、历史/恢复边界及直接测试。
- 原因：已有文件经 copyFile 覆盖不能仅凭函数名宣称原子。保留桌面文件对象是已有需求，需要和耐故障目标一起设计。
- 先失败测试：临时写入失败、复制中断、目标覆盖失败、磁盘满/权限拒绝、进程终止、备份恢复失败、符号链接授权、同一文件并发保存。成功后检查文字/编码与文件身份；故障后检查旧确认版本仍在或可恢复，不能只断言 Promise reject。
- 实现：先写短 ADR 比较替换写入与带恢复记录的身份保留写入，定义持久化顺序、恢复材料、清理时机和冲突策略。复用可信路径与 expectedMtime；不得通过复制绕过授权或将用户内容写进仓库。不要以删除备份来使测试“无残留”。
- 验收：协议 Q01 故障矩阵全部通过；每个可注入阶段至少 20 次重复；已确认版本 100% 可保留/恢复；恢复失败保留材料与可操作提示，不能误报成功。三平台文件对象需求按支持范围验证。未做硬件掉电测试不能宣称任意掉电零丢失。
- 回退：回退应用代码前保全恢复材料；新元数据有向后兼容读取或明确降级路径，不删除正文和历史。

### S02 / P0：保存确认、快照身份与关闭安全

- 范围：`document-session/ensure-snapshot.ts`、`useDocumentSaving.ts`、save queue、Editor adapter/instance/listener、关闭桥接和会话恢复。
- 先失败测试：pending=true 且缓存等于上次保存时立即关闭；settled=false；等待中切到另一文件；卸载/工作区切换；保存时继续输入；IME 提交后立即保存；保存成功回调晚于新输入。必须断言磁盘、dirty、活动文档身份和窗口是否关闭。
- 最小契约：保存请求有目标文档/session 与编辑版本（或同等可证明令牌）；快照属于该文档且不早于目标版本；磁盘回执仅确认实际写出的版本。异步读取不能追随已切换的 editorRef 取得别篇内容。
- 超时：不能把旧快照当本次输入已保存，不能自动允许关闭。保留 dirty、可重试/取消；如保留旧快照作恢复材料，说明其性质，不能用 toast 代替关闭阻断。
- 验收：Q02 所有核心组合通过，5 MiB/普通/阈值两侧至少 30 次定向时序重复；成功保存包含目标版本，后续输入未确认则 dirty=true；超时/取消/冲突不能误关。主进程窗口关闭只接受明确完成。
- 文档：domain-model、document-tab-lifecycle、system-file-open-and-close、必要的 DTO/错误码/迁移说明。

### S03 / P0 正确性、P1 性能：消除实际瓶颈

- 范围：Editor content/viewport/instance、序列化监听、AppComposition/历史快照获取、生产索引/搜索、Electron 性能脚本。
- 方法：分别测解析、编辑状态装载、DOM、序列化、IPC、写盘、导出；先移除无关重渲染触发的全文序列化，再评估增量/Worker。不能仅通过放宽超时、换小夹具或保存旧内容“优化”。
- 验收：既有真实 Electron 硬门禁完整通过，原文尾部与末次输入均落盘；同时达到 M01 体验目标：普通输入 P95≤50ms，普通保存≤500ms，20 标签切换≤300ms，5 MiB 打开≤10s/保存≤5s，均按协议采样。达硬门禁而未达体验预算则 P0 性能阻塞可按安全证据结案，P1 体验仍未完成，G1 优势不得宣称成立。
- 内存/长运行：8 小时合成写作+搜索+切标签，监听/定时器随会话回到预期基线；Main/Renderer 分别测量，末 2 小时稳定窗口中位内存较首个稳定窗口增长≤15%且≤100MiB，无连续增长趋势；超出则调查，不能强制 GC 掩盖。
- 未达标：保留明确容量限制与问题，不能以只读降级代替 5 MiB 编辑验收；若调整支持范围，另行修改产品承诺、兼容矩阵和发布计划，不静默豁免。

### S04 / P0 发布门禁：候选包与试用信任说明

- 提前准备 Windows/macOS/Linux 测试资源、安装身份/旧配置/签名与升级说明；已有 workflow 的配置不重复建设。
- 可信试用要求对应平台候选包安装、启动、文件关联、保存/恢复、卸载保留用户文件均通过；安装包和合成测试配置隔离。不使用安装器覆盖用户已有设置验证。
- 验收：每个开展真实试用的平台至少 2 个独立测试环境，每个完整安装流程至少 3 次；无 P0、安全/数据缺陷或未解释的安装失败。平台不足则不招募该平台真实库试用。
- 试用说明必须包含标准文件共存、已知语法/容量/导出限制、恢复方法与反馈入口。试用不能被宣传为全平台正式发布；完整三平台门禁仍由 S14 执行。

- 先失败测试：新查询替代旧响应、取消/失败保留输入、5000 预算尾部命中、结果数/文件数/深度分别截断；未扫描不得显示成确定的无结果。

- 范围：搜索面板、反链面板、Editor adapter 命令、`app/actions/`、来源与导航纯函数。超限文件先拆职责。
- 交付：预览片段 → 插入标准 Markdown 相对链接，或“引用片段 + 来源链接” → 返回原文章原位置继续写作；原文件不被修改，插入可单步撤销。
- 引用契约：第一版是带来源的文本快照，不是实时转嵌；不承诺学术引文规范。优先 Markdown 标准链接，标题锚点按兼容规则生成；源文档变更/移动后无法定位时明确失效，不能把普通文件路径变成只能在 Paperin 打开的内容。
- 先失败测试：中文标题、同名文件、源删除/重命名/修改、跨库外部来源、异步预览后目标标签变化、IME、重复点击、无选区、插入后撤销；禁止将旧结果插入已经换成的另一篇文档。
- 验收：Q05 来源/位置/撤销矩阵全过；键盘与鼠标均能完成；任务 R02 至少 10/12 成功且配对中位耗时改善≥30%，质量不下降。自动测试通过而用户任务不通过，功能实现可记录，战略优势仍待验证。
- 文档：command-panels、兼容矩阵、来源快照含义和失效行为。

### S09 / P1：下次打开还能继续

- 范围：已有 WorkspaceStateBundle、document session、最近编辑/收藏和轻量导航状态；不新增重复正文和无限历史。
- 交付：保留搜索查询与阅读/写作往返位置；重启可恢复经允许保存的视图状态；最近引用作为按需入口，不做自动打卡提醒。
- 验收：两次真实重启、跨工作区、同名不同路径、改名/删除、关闭标签后返回、旧异步响应均不串文档或创建重复标签；正文和文件引用一致。Q05 全过；5 名实际试用者次日能独立继续原任务。
- 迁移：旧设置缺字段走默认值，恢复失败保留原记录；可关闭/清除导航记录且不删正文。

### G1 退出

S05–S09 工程门禁通过；R02 任务、M01 体验目标通过。若两轮改进仍不能减少任务成本，先复核画像/任务，不直接进入 AI 和更多图谱。

## 6. G2：可交付成果与固定使用

### S10 / P1：现有导出的质量与预检

- 范围：`hooks/exports/`、`lib/docx.ts`、`lib/export-bundle.ts`、Main 导出/打印 handler；复用现有发布弹窗，不新建发布服务。
- 顺序：Markdown/HTML/PDF → DOCX 明确子集 → 其他现有格式准确说明依赖。公式转图片、特殊语法降级等逐格式登记；Pandoc/字体未安装需预检，不把入口可点击当支持。
- 先失败测试：缺图片/断链/未安装依赖、取消对话框、权限/空间不足、导出中改文档/切标签、并发提交、打印窗口关闭/卸载；网络响应、HTML、CSS、Data URL 复用白名单/转义/大小限制。
- 验收：E01 的 12 篇合成文档×4 核心格式×承诺平台全部跑完；已支持正文和来源 100% 正确、附件齐全；PDF/DOCX 按页人工检查无中文乱码、内容截断或丢页；不支持项明确预检/降级。普通 HTML/PDF/DOCX P95 分别≤3s/5s/8s；大文档另按分层边界验证，失败不得覆盖原文件或误报完成。
- 导出前检查先做确定性规则：缺附件、断链、支持范围；未完成任务/元数据只是提醒，不能自行删除正文。导出产物通过自身打开/解析检查，不只检查文件存在。
- 文档：导出支持子集、依赖、分页/字体、错误处理与平台矩阵。

### S11 / P1：两个可携带任务模板

- 首版只做“技术文章/教程”“项目方案/决策记录”。标题、问题、资料来源、自己的结论和交付检查均为普通 Markdown；不建立模板市场或自有字段数据库。
- 验收：每个模板至少 5 名目标用户使用，至少 4 名无需讲解完成起步；模板生成不覆盖同名文件、不改原模板，取消/失败可恢复；在其他 Markdown 编辑器可读；使用模板不强制写品牌署名。
- 与 S13 共用样本，工程工期包含资源、直接测试和说明，实际用户招募耗时另计。

### S12 / P1：最小研究与指标记录

- 优先使用自愿研究日记和匿名编号汇总；不为本轮研究默认新增遥测后端。若实现本地计数，走 Main 设置/独立存储；不把正文/path/search term 当统计字段。
- 交付：A01/R02/C01 指标字典、同意/退出/删除说明、每周脱敏汇总模板；本地信号和用户自报分开，无法测量写未知。
- 验收：Q06 schema 白名单测试和样例审核通过；不上传正文、路径、标题、查询、原文 hash 或文档可逆标识；默认无研究上传请求；可预览导出、撤回/删除；关闭研究不影响任何核心流程。
- 不增加强制账号和跨设备追踪。若未来需要网络遥测，单独设计 consent、保留时间和安全边界，不借本任务默认上线。

### S13 / P1：对比任务与两批四周使用

- 第一轮 12 人做 A01/R02，可在已通过 G0 的候选上进行；保留常用工具的配置，不人为削弱竞品。任务材料等价、顺序交叉、失败和帮助均计入。
- 第二轮两批各至少 20 名已激活用户，间隔一周入组，观察各自 28 天；至少一半来自非熟人圈。不以强制提醒/奖金条件要求回访，受提醒和受激励行为另列。
- 验收：每批 14 天有用成果率≥50%；W4 有效留存≥40%；W4 复用留存≥25%；报告分子/分母、失访和区间，不将小样本包装为 PMF。至少访谈 5 名流失用户（不足则访谈全部可联系且同意者并记录缺口）。
- 未达标：每轮只选最大阻塞修复；两轮仍失败触发战略复核。数据缺失不能“按感觉”判通过。

### S14 / P0 发布门禁：全部承诺平台与回退

- 范围：打包与 workflow、更新/版本替换、安装身份、文件关联、配置/草稿迁移和发布说明。不把有最新版本元数据当作已实现自动更新。
- Windows：安装/升级/启动、资源管理器关联、中文路径、文件对象需求、多窗口、权限、保存冲突和导出；macOS：Finder open-file、菜单/键位、权限、签名/公证或真实限制说明、升级；Linux：声明的包格式/桌面环境、MIME、字体、权限、保存/输出和版本替换。
- 验收：S04 环境要求扩展至全部三平台；当前 release commit 的质量/安装/恢复证据齐备；实际 CI run 与产物匹配；无未解决 P0；Q01–Q06、E01 和回退演练通过。打包成功不能代替系统安装行为。
- 工作流必须能让候选验证先于正式发布；检查现有 tag/manual → release 路径是否真正覆盖所需门禁，缺口补齐。不要在文档工作中打 tag、推送或触发发布。
- 回退：升级前/迁移后/失败中断各有备份与恢复验证，卸载/回退不删除用户文件；新 schema 不兼容旧版时提供明确恢复步骤，禁止默默重置设置与草稿。
- 支持范围若要改为某平台先行，须独立修订产品承诺、兼容矩阵和验证计划；本版不自动豁免三平台完整发布要求。

### G2 退出

S10–S14 全部适用门禁通过，两个成熟队列达标，G0/G1 无回归。可记录“首轮定位得到验证”；尚不能宣称大规模产品市场匹配或收入成立。

## 7. G3：增长与商业验证

### S15 / P2：一个可重复渠道

- 从战略渠道表选择两个，逐轮固定受众、任务文案、落地指南与投入上限，先做小实验。产物为两份迁移/工作流教程、至少三个经许可脱敏案例和反馈处理说明。
- 验收：至少一个渠道的两轮样本各有≥20 名已激活用户、成熟 W4 留存≥40%，或样本不足继续积累不扩投；报告到达/激活/W4、现金和人力成本。可以复用 S13 后续队列但须预先记录来源，不事后选赢家。
- 规模到 100 名可观察 WAU 后，连续四周核心阻塞工单≤5/100 WAU、支持≤4 小时/周。未达标先修产品，不以客服超负荷维持增长。
- 两轮无激活或留存信号就调整/停止该渠道；下载/点赞/进群数不能单独结项。联系、发帖与支出由后续授权范围执行。

### S16 / P2：专业交付是否值得付费

- 对≥15 名完成过核心任务的用户提供交付样例，比较一次性购买与年度维护表达；先用现有输出验证，不先开发大套收费功能。
- 验收：价格/成本/退款假设有记录；真实实验至少 5 名非关联付费用户、观察 30 天退款与支持成本，贡献毛利为正；规模获客预期回收≤6 个月。没有支付记录则只能完成需求研究，商业仍未验证。
- 两轮无付费信号暂停收费扩建；不得修改历史授权、关闭数据恢复/迁出或用 AI 成本补贴掩盖亏损。

### S17 / P1：跟随功能消除维护债务

- 每次触及 file-handlers、useWorkspaceFiles、useAppSettings、AppComposition、Editor instance/overlays、Mermaid、docx 等模块，按当前实际行数和职责评估，禁止引用历史行数当验收。
- 验收：被修改生产文件不得超过 450 行仍继续新增功能；组件按 250 行/异步/状态规则拆分；新边界直接测试通过，旧契约和行为保持；没有机械拆出另一超大 hook。每次目录移动同步 import/测试/构建/维护说明并全量验证。
- 不在无触及需求时重构整个仓库。已超限但暂不修改的模块进入维护账本，不被误称为全部债务清零。

## 8. 首个两周与依赖路径

1. 第 1–2 个工程日：S00 冻结当前失败和证据，复核平台资源；同时准备招募和 S12 指标字典。
2. 第 3–7 日：S01 故障测试先行，确定身份保留与恢复方案，验证后独立提交。
3. 第 8–10 日：S02 优先补超时关闭、等待中切标签测试和快照身份设计；按实际发现继续，不承诺两周全部解决。
4. S02 完成后 S03 分段性能，S04 候选验证；通过 G0 才扩大真实库试用。
5. S05/S06/S07 → S08 → S09；S10 在保存稳定后推进，来源检查依赖 S08；S11 补最小模板。
6. S12 准备贯穿早期，S13 队列观察与 S14 平台验收重叠；G2 成立才进入 S15/S16。

设计与夹具准备可提前，高风险保存/恢复实现保持串行。日期到期但门禁没过时顺延，不删断言、不改分母、不把 P0 降为已知限制完成发布。

## 9. 任务结项模板

每个任务的状态从“待做 → 进行中 → 工程验证通过 → 用户/平台验证通过 → 完成”推进，不适用项必须说明理由。

```text
任务 ID / 优先级 / 负责人 / 代码 commit：
问题或假设 / 原证据 / 影响场景：
变更边界 / 数据与 schema 影响 / 回退方式：
先失败的测试和结果：
typecheck / test / build / 适用 smoke、a11y、性能、平台：
指标 ID / 夹具版本 / 环境 / 样本 / 分子分母 / 未达标项：
文档与证据链接 / 用户研究限制：
结论：工程完成、产品验证通过或继续阻塞（分开写）
```

工程结项要求测试/文档/提交齐备；功能优势结项还要求用户任务指标；发布结项还要求全部承诺平台；商业结项还要求真实付费。最终达到战略定位的标志是 G0–G2 的完整证据链，增长发展还要有 G3 的可重复获客与可持续成本。
