# Paperin 界面与交互规范

更新时间：2026-09-21（Asia/Shanghai）

状态：当前生产界面规范与验收基线；已实现部分以 [PROJECT-STATUS](PROJECT-STATUS.md) 为准，不改变现有快捷键和用户设置。

依据：[2026-09-22 产品战略发展报告](PRODUCT-STRATEGY-REVIEW-2026-09-22.md)、生产组件与 quiet-workspace 已有设计；具体完成度以 [PROJECT-STATUS](PROJECT-STATUS.md) 为准。

## 1. 设计目标

保留“安静、清晰、本地文件可掌握”的气质。持续优化重心是**降低信息重复、提高状态可信度和操作可发现性**，不增加装饰层或更换整套视觉系统。

用户在任何时刻应能回答四个问题：

1. 我在哪个知识库？
2. 当前文件在哪里？
3. 最新内容是否已写入磁盘？
4. 如何找到旧资料、回到刚才的位置？

UI/UX 技能检索提供了键盘、焦点与信息层级参考。其自动设计系统首次返回营销页面的 Hero/CTA 与不相关配色，已拒绝套用；改用定向 UX 查询。本文版式与绿调方向来自当前产品，不引入营销组件、远程字体或新 UI 框架。

## 2. 信息架构与界面草图

默认桌面布局由“知识库导航 + 当前文档 + 可选上下文”组成。面板可收起，知识库上下文仍有恢复入口；外部文件沿用同一工作台。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 侧栏  菜单     [当前笔记.md ●] [另一篇.md]       专注  大纲  更多   窗口控件 │
├──────────────────┬───────────────────────────────────────────┬───────────────┤
│ 我的知识库 ▾     │ 学习 / 方法 / 当前笔记.md        定位到文件 │ 大纲       ▾  │
│ 搜索文件与命令   │                                           │               │
│     Ctrl+P       │ 文档中实际存在的标题                      │  引言         │
│ 最近编辑         │                                           │ ▌当前章节     │
│ 我的收藏         │ 正文                                      │  方法         │
│ 全部文件     ＋  │                                           │  结论         │
│                  │ 保留可调阅读宽度，宽表格可局部滚动。      │               │
│ ▾ 学习           │                                           │               │
│   ▾ 方法         │ 编辑器负责正文与撤销历史。                │               │
│     当前笔记.md  │ 路径条、收藏和状态均在正文模型之外。      │               │
│                  │                                           │               │
│ 外部文件         │                                           │               │
│     临时资料.md  │                                           │               │
├──────────────────┴───────────────────────────────────────────┴───────────────┤
│ 已保存到本地                                             字数  阅读时长  ⋯ │
└──────────────────────────────────────────────────────────────────────────────┘
```

草图表达职责，不是最终视觉稿。示例文件名与数字为合成内容；不自动给用户 Markdown 增加 H1、日期、分类或元数据。

### 区域职责

| 区域 | 常态承担的信息 | 条件性信息 / 入口 |
| --- | --- | --- |
| 左侧导航 | 库名、文件与命令入口、最近、收藏、文件树 | 库切换、索引覆盖、外部文件分组 |
| 顶部标签区 | 活动文件、dirty、标签切换 | 固定、预览、排序、关闭组、溢出列表 |
| 文档路径条 | 相对路径、文件定位 | 外部来源、未命名/示例提示、明确重命名入口 |
| 正文 | 实际 Markdown 内容 | 编辑上下文工具，按选区或当前块出现 |
| 右侧上下文 | 用户选择的大纲或其他面板 | 关系、标签、属性、检查仍由 PanelRegistry 提供 |
| 状态栏 | 保存进度/结果、字数 | 编码、行列、选中统计、索引状态展开查看 |

“不重复”是常态展示规则，不禁止必要的安全冗余：dirty 仍需同时在标签、窗口关闭逻辑与窗口状态反映。错误必须出现在可采取行动的位置，不能仅藏在状态栏。

## 3. 顶栏与文件定位

### 3.1 顶栏

- 延续当前单条约 52px 顶栏；优先给标签留空间。
- 将工作区名的常驻展示集中到侧栏标题；侧栏收起时顶栏展示简短库名和恢复按钮。
- 删除顶栏右侧第二个常驻可编辑文件名。重命名从标签右键/文件菜单与路径条明确动作进入，复用现有保存和重命名规则。
- 常态高频动作保留专注、上下文开关和更多；设置统一为一个主要入口，主题快切放入外观设置或更多。
- 桌面菜单功能完整保留。窄宽度时收敛为菜单按钮，支持键盘打开、箭头导航和 Escape；命令面板是快捷路径，不能是唯一发现路径。
- 窗口拖拽区与全部可点击区分离；标签、关闭钮、菜单、标题输入和恢复按钮均不可成为拖拽区。保留 Windows 原生窗口按钮区域和 macOS 交通灯空间。

### 3.2 标签

- 选中项用背景/底线与 `aria-selected` 共同表达；dirty 用明确标记和可访问名称表达。
- 同名文档通过相对目录消歧，悬停与键盘焦点均可获得完整名称；不同目录的同名文件不能互相替换。
- 20 标签时允许横向浏览与“全部标签”列表，活动项自动进入可见范围；不把所有标签压成无法识别的短线。
- 延续固定、预览标签、拖拽排序与关闭确认语义；视觉简化不能删除已有行为。

### 3.3 面包屑与正文标题

- 在正文滚动区上方提供约 28–32px 的轻路径条；高度计入文档区域，不能再演变成三条工具栏。
- 库内显示相对路径；点击目录定位/展开侧栏，文件动作通过清楚的按钮或菜单进入。
- 外部文件显示“外部文件”和可展开路径，不默认移入库、不自动纳入库索引。
- 未命名显示“未命名 · 尚未保存到磁盘”；示例显示“示例文档 · 另存为后保留修改”。
- 文件名与正文 H1 可以不同，两者不自动双向改写。重命名成功后同步标签、树和路径条；正文内容只通过用户编辑改变。
- 没有 H1 的 Markdown 正常显示，不由壳层插入伪标题，也不把文档头部的元信息持久化为正文。

## 4. 导航与搜索

### 4.1 侧栏

建议默认宽度 260px、可调约 220–320px；实施时结合现有布局存储校验范围迁移，保留用户宽度。

- 标题承载库名与切换入口；文件树不必再次展示一个占行的同名根节点，可通过集合标题保留根级创建/折叠操作。
- 左侧“最近编辑”与“我的收藏”保留，不增加多个默认空集合。
- 文件行建议高度 28–32px、字号 13–14px、图标 16px；选中态有文字与背景差异，不能仅改变极淡图标色。
- 提供“定位当前文件”，可按用户偏好自动展开祖先；只展开相关路径，不每次刷新都重置折叠记录和滚动位置。
- 收藏恢复必须完成后再宣称持久化。对删除/移动/重命名后的引用有明确迁移或失效提示；不能默默打开旧路径失败。
- 文档统计采用明确命名：全部文档、筛选命中、已索引文档分别处理。外部临时文件不混入库内总数。
- 空收藏显示“还没有收藏，可在文件菜单中收藏”；空最近列表显示“打开或编辑文档后会出现在这里”，不只重复标题。

### 4.2 搜索入口语义

保留现有快速打开与全文搜索实现，先通过一致入口连接，不在侧栏新造第二套搜索算法。

| 用户意图 | 行为 | 当前快捷键策略 |
| --- | --- | --- |
| 找文件 | 名称/路径匹配，显示目录消歧 | 默认 `Ctrl+P`，展示实际映射 |
| 找命令 | 快速打开中进入 `>` 命令模式，提供可点击切换 | 不另占与编辑器冲突的快捷键 |
| 找正文 | 明确切换为“搜索知识库内容”，显示范围与片段 | 保留现有命令入口；新增绑定前做冲突检查 |
| 当前文档查找 | 在当前编辑器内定位 | 默认 `Ctrl+F` |
| 插入链接 | 编辑器链接能力 | 保留 `Ctrl+K` |

所有键位文案从同一配置读取；macOS 使用平台友好的组合键展示，但执行仍经过现有归一与冲突规则。用户改键后侧栏、菜单、命令面板和帮助必须同步。

### 4.3 搜索结果

- 文件名 + 相对目录 + 命中片段 + 匹配位置；同名文件必须可区分。
- 先沿用现有文件名排序，逐步补“精确标题 > 前缀 > 包含 > 路径”，再评估正文相关性；不要在缺乏数据时直接上向量库。
- 标明查询范围和当前过滤；文件查找与全文查找结果不能混淆。
- 本轮可先把现有全文搜索弹窗接入统一入口；用户验证后再决定是否迁至侧栏常驻结果。不要同时重写 UI 宿主和搜索服务。
- 持续查询时允许取消；工作区变化或新请求发生后旧结果失效。打开结果沿用 `useWorkspaceViewModel.reveal`，最后一次选择获胜。
- 点击结果保留查询/滚动/筛选；提供回到上一个文档位置的路径，避免每次查资料都丢失正在写作的位置。
- 超出扫描预算和超出结果数量上限分开说明。当前产品索引/搜索覆盖预算为 5000 文件，索引还限制单文件大小；不能展示“无结果”却不说覆盖不完整。
- 明确区分未查询、查询中、无匹配、部分结果、失败与取消。失败保留搜索词并给出重试入口。

## 5. 正文版式与上下文面板

### 5.1 排版建议值

这些是首轮原型的初始值；实际通过小屏、缩放、长文试用校准，不覆盖用户的 `--efs`、`--ecw`、`--elh`。

| 项目 | 建议初值 | 约束 |
| --- | --- | --- |
| 正文字号 | 16–18px | 中文可读，支持用户调节与缩放 |
| 正文行高 | 1.75–1.9 | 根据字体和列表密度验证 |
| 舒适阅读宽度 | 约 720px | 可选约 680–800px，不能直接判现有窄设置错误 |
| 宽内容预设 | 约 960px 上限 | 用于技术文档、表格，不强迫普通段落铺满窗口 |
| H1 | 30–36px | 使用真实内容标题，中文不套用过紧负字距 |
| H2 / H3 | 23–26px / 19–21px | 层级靠尺度与留白，不每级都加粗边线 |
| 段落间距 | 约 0.8–1em | 避免列表和连续段落产生过长滚动 |
| 图标与控件 | 图标约 16–18px，常用按钮约 30–32px | 命中区可扩展，不等于图标外接框 |
| 状态栏 | 约 24–28px | 正常状态文字建议 12–13px，可读而不抢正文 |

字体优先使用已有系统中文字体栈与本地字体；不依赖在线字体加载。表格、长公式和代码块使用局部滚动，不让整个工作台横向滚动。选择高亮、光标所在块样式和真正的标题底色应分别复查。

### 5.2 右侧大纲

- 在现有 ContextDock 中增加“仅大纲”轻展示，建议宽 200–240px；关系/属性/检查保留约 280–320px 的完整面板。
- 模式是同一 dock 的呈现变化，不创建第二套大纲状态、滚动监听和持久化机制。
- 默认显示标题和当前章节；章节字数放到面板选项、选中项详情或统计视图，不能只靠 hover 才可访问。
- 一级/二级标题清楚，较深层级可折叠；长中文标题允许合理换行或完整名称提示，不让字数挤占标题空间。
- 当前章节跟随滚动，但不抢输入焦点；用户主动滚动大纲期间避免反复拉回。
- 右侧“关系/标签/属性/检查”等切换有文字提示和可访问名称；没有适用内容时说明原因。
- 用户关闭 dock 后保留恢复入口；“展开/窄栏/收起/隐藏”含义需统一，避免底部箭头与叉号无法区分。

## 6. 状态设计：可信先于漂亮

文档类型与保存状态为独立维度。UI 可以先建立派生视图模型，不为显示文案立即破坏共享持久化 schema。

2026-09-15 已落地首项派生语义：顶栏与状态栏共用 `documentSaveStatusLabel`，将磁盘文件、示例、未命名三种存储身份与 dirty 独立组合。无盘文档即使没有编辑也不显示“已保存”；示例已编辑和未命名已编辑保留修改提示。路径条保持来源/路径职责，三处真实 Electron 冒烟已核对一致。保存中、冲突、编码损失和保存失败会覆盖“已保存/未保存”文案；另存为与普通保存的磁盘回执如果晚于新快照或未落账输入，不会把文档标成已保存。真实中文输入法与九主题缩放矩阵仍需人工验收。

| 状态 | 建议可见文案 | 允许的下一步 |
| --- | --- | --- |
| 示例，未修改 | 示例文档 | 另存为、继续阅读 |
| 无磁盘路径 | 尚未保存到磁盘 | 保存时选择路径；关闭按已有确认规则 |
| 加载/流式装载 | 正在打开文档… | 可取消；不能编辑半截正文并保存 |
| 已编辑，快照未就绪 | 有未保存修改 | 等待/准备本次保存；不能提前显示成功 |
| 保存中 | 正在保存… | 防重复提交；继续输入仍被正确记录 |
| 磁盘确认当前版本 | 已保存到本地 | 展开查看保存时间/编码 |
| 保存旧版本后又有输入 | 有新的未保存修改 | 继续自动保存或再次手动保存 |
| 外部冲突 | 文件已被其他程序修改 | 查看差异/另存为/明确覆盖；取消保留内容 |
| 编码不兼容 | 当前编码无法保存这些字符 | 选择保留原编码或改用 UTF-8，不能丢字 |
| 权限/文件不存在 | 保存失败，编辑内容仍保留 | 重试、另存为；关闭不能悄悄放弃 |
| 恢复记录存在 | 发现可恢复的编辑 | 比较并选择恢复；恢复后按 dirty 处理 |

保存成功只能代表对应快照已得到磁盘确认；“已备份草稿”不能替代“已保存原文件”。冲突或编码对话框打开期间继续输入，确认后不得把新输入当作已经保存。

保存失败用持续、可操作反馈；普通成功状态用轻量状态栏，避免每次自动保存都 toast。读屏 live 区域只播报关键状态转移，不能每次光标移动都重复整条路径。

## 7. 空状态、首次使用与设置

### 首次使用

- 无知识库时主要动作是“打开知识库文件夹”，其次为“新建笔记”“打开文件”。不要求登录，不自动扫描任意目录。
- 有知识库但无活动标签时展示“继续最近编辑”或“在此知识库新建”，保留侧栏；不强行重新打开欢迎页或图谱。
- 示例文档通过单独入口进入，不混同为真实知识库已保存文件。
- 首次打开已有目录只说明兼容范围、索引进度和必要限制；不自动格式化、重写链接或转换附件。

### 设置

- 当前已经放大的设置弹窗先验证可见范围、滚动和焦点，不继续以“再放大”为主要优化。
- 外观页加入真实主题样张：同一段中文、标题、链接、代码、选中与错误状态；缩略卡用于选择，完整预览仍可访问。
- 设置区分应用默认与当前知识库覆盖，明确“跟随系统”的来源；切主题不能重置字体、宽度或行距。
- 将内容字号、阅读宽度、行高整合为直观预设 + 可调参数；显示恢复默认的影响范围。
- 低频导出、图床、更新等使用清楚分组；加载/保存失败可见，不以关闭弹窗表示成功。
- 「自动检查更新」在高级面板，有可访问名称；关闭后下次启动不检查、不自动下载、退出时也不安装已下载包。
- SM.MS 凭据失败必须可操作：安全存储不可用或迁移失败时不得显示「已配置」，并回退本地附件。拼写检查保持默认关闭的现有开关，打开后可能下载词典且不上传正文。

## 8. 响应式、键盘与主题

桌面优先，以下断点为候选值，必须用真实窗口尺寸和系统缩放验证。不要把网页移动优先模板直接用于桌面工作台。

| 内容区可用宽度 | 建议行为 |
| --- | --- |
| ≥1440px | 侧栏 + 正文 + 可选轻大纲；正文宽度遵循用户设置 |
| 1100–1439px | 侧栏保留；右 dock 默认按需，避免挤压正文 |
| 820–1099px | 菜单/顶栏进一步收敛；按可用宽度收起一个辅助面板 |
| <820px | 侧栏与上下文均走同一抽屉协调器，一次只打开一个模态抽屉 |

抽屉和对话框共用明确的遮罩层级、Escape、焦点圈定与恢复策略。打开右抽屉时左抽屉退出；全屏公式/图表等特殊视图也纳入层级测试。宽度变化应保留用户偏好，但不能恢复出遮挡整个编辑区的旧布局。

键盘要求：

- 全流程可用键盘完成；Tab 顺序跟随视觉顺序，树有方向键/展开/收起/打开策略，菜单和标签支持自己的导航模式。
- IME 组合态中 Enter/Escape 属于输入法，不触发保存、搜索提交、重命名或关闭浮层；同时验证 composition 事件和实际中文输入法。
- 恢复焦点应落回原触发控件；触发项已被删除则落到合理替代，如相邻标签或编辑区。
- 指针拖拽有键盘替代；缩放和减少动态效果不影响完成任务。

颜色按语义拆分，例如正文、辅助可读文字、停用文字、装饰分隔线、必要控件边界和焦点环。正常辅助文字仍应按实际背景校验 4.5:1；必要的非文字控件信息按 3:1 校验，装饰线单独处理。[W3C 文字说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[控件对比说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

常见桌面按钮建议约 30–32px 命中区；细小的标签关闭钮/折叠钮扩大实际命中范围并检查间距。WCAG 2.2 AA 的目标尺寸条款以 24×24 CSS px 为基准并有例外，44×44 是更强目标，不能把它写成所有桌面按钮的 AA 硬要求。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。
