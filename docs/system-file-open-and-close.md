# 系统打开、多窗口与关闭规则

本文固化系统文件关联、启动参数、多窗口与关闭保护的当前契约。系统打开最终复用 Renderer 的文档标签打开路径，不创建第二套文件模式。

## 打开规则

| 入口 | 单窗口设置 | 多窗口设置 |
|---|---|---|
| 安装包文件关联 / 启动 `argv` | 恢复正常窗口和上次知识库，再把文件作为当前窗口标签打开 | 创建 `#fresh` 隔离窗口，只打开该文件，不恢复或写入共享会话/草稿 |
| 已运行应用收到 `second-instance` | 还原并聚焦现有窗口；若参数含 Markdown 文件，则送入该窗口 | 多窗口设置不申请单实例锁，每个进程按上一行处理自己的启动参数 |
| macOS `open-file` | 窗口存在时复用，不存在时创建正常恢复窗口 | 为文件创建 `#fresh` 隔离窗口 |
| 应用内“在新窗口打开” | 始终创建 `#fresh?file=...` 隔离窗口 | 相同 |

同一路径重复打开只聚焦已有标签。Windows 比较忽略大小写；启动参数进入 Main 时还会做平台路径规范化和去重，最多接受 20 个文件，避免异常参数制造无界标签。

主窗口初次显示使用 1200×800 的居中位置，并保持普通窗口层级（不置顶、不跳过任务栏）。Windows、macOS 和 Linux 保存已有文件时都保留原文件对象，避免桌面环境把文件当成新项目重新排列图标；应用不会调用桌面图标排列或移动 API。

安装包声明 `.md` 和 `.markdown` 为 Paperin 可编辑文件。Main 只接受绝对、本地且扩展名匹配的路径，并在 `stat` 确认为普通文件后授权：正文只获得文件级读写信任；父目录仅获得相对图片读取权限。URL、相对路径、其他扩展名和不存在的文件不会送入 Renderer。

## 外部临时文件

不位于当前知识库根目录的系统打开文件显示为“外部文件”标签。该链路只调用 `document.read` 和现有文档会话，不调用 `openFolder`、索引刷新或工作区结构写入。关闭标签会从统一 `DocumentRecord` store 删除该会话记录和草稿，不删除磁盘文件，也不改变知识库索引。

## dirty 与关闭保护

- dirty 状态来自编辑器实时内容与最后保存基线，标签、当前文件横幅和主进程窗口状态使用同一口径。
- 关闭磁盘文件或窗口前，保存队列使用该文件的 `expectedMtime` 冲刷最新内容；`CONFLICT`、编码失败、权限失败或超时不得静默覆盖。
- 未命名 dirty 文档让用户选择保存、不保存或取消。另存为取消会保留原标签与内容。
- 磁盘文件保存失败时让用户选择放弃修改或取消；取消返回 `false`，Main 保持窗口打开。关窗保存超时或异常同样保持窗口并给出提示。
- Main 只有收到 Renderer 明确返回 `true` 才销毁窗口，因此取消、失败和未完成分支不会丢失 dirty 会话。

## 验证范围

自动测试覆盖启动参数过滤/路径规范化、Windows 大小写去重、单/多窗口分流、preload 订阅清理、外部记录关闭、关闭保存结果，以及打包关联元数据。Electron smoke 在本 Windows 环境使用真实构建产物验证：外部 Markdown 启动参数进入 Renderer 外部标签，同路径事件不会增加标签数；随后继续验证工作区打开、保存冲突、重读、重命名和搜索。`electron-builder --win --dir` 也已成功生成 Windows unpacked 应用，确认关联配置可被打包器接受；该步骤不等同于安装后注册表验证。

仍需发布前平台验证：

- 安装 Windows NSIS 后由资源管理器双击 `.md`/`.markdown`，检查系统默认应用注册和卸载清理。
- macOS Finder `open-file` 与 DMG 文件关联；Linux 桌面环境 MIME/default-app 行为。
- 多个真实安装包实例同时编辑不同文件时的人工关闭、任务栏聚焦与输入法冒烟。

这些平台结论没有由本机开发态测试代替或标记为已通过。
