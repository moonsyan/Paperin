# Paperin 产品整体工作流

更新时间：2026-09-22（Asia/Shanghai）

本文定义 Paperin 从用户发现产品到持续维护文档的完整工作流，以及每一步对应的代码边界、失败分支和验收信号。产品定位与阶段取舍见[产品战略发展报告](PRODUCT-STRATEGY-REVIEW-2026-09-22.md)，具体开发顺序见[实施计划](superpowers/plans/2026-09-22-product-workflow-implementation.md)，当前通过和失败项见[项目状态](PROJECT-STATUS.md)。

## 1. 核心结果

Paperin 服务的不是“多写一篇笔记”，而是以下可重复结果：

> 用户从自己的项目资料中找到依据，写成一份带来源、可安全保存、可继续维护、可交付的 Markdown 文档。

主工作流：

```text
发现与安装
  -> 首次启动并理解边界
  -> 打开自己的文件或知识库
  -> 找到相关资料
  -> 插入来源并写作
  -> 保存、关闭与恢复
  -> 检查来源和文档质量
  -> 导出或发布成果
  -> 下次回来继续维护
  -> 在不泄露正文的前提下反馈问题
```

团队和企业方向只能从“个人作者向团队交付可靠成果”继续延伸，不能绕过个人工作流直接建设账号、权限或实时协作。

## 2. 全局不变量

所有阶段必须遵守以下不变量：

- 用户 Markdown 是事实源；草稿、会话、索引、统计和设置不能替代正文文件。
- Renderer 不读取文件系统；所有文件和设置能力只能经 typed `window.desktopAPI` 进入 Main。
- 保存必须带期望版本；冲突、编码损失、取消和失败不能冒充成功。
- 搜索、索引、来源检查和导出必须说明覆盖范围；没有扫完不能显示成“没有结果”。
- 来源插入保存的是用户选择的片段快照和普通 Markdown 链接，不修改来源文件。
- 诊断、交付报告、性能记录和反馈材料不得包含正文、绝对路径、token 或搜索词。
- 自动测试、Electron 冒烟、安装态验证和用户任务是四种不同证据，不能互相替代。
- 未达到阶段进入条件时停止扩张，不用新增功能掩盖性能、发行或用户价值红灯。

## 3. 工作流阶段

### 3.1 发现、下载与安装

**用户目标：** 知道 Paperin 解决什么问题，下载与当前平台匹配的可信安装包。

**产品行为：** 发布页说明“资料到可维护交付文档”的任务、平台范围、联网行为、已知限制、校验信息和卸载后的数据归属。候选版本只能生成 Draft Release；正式发布必须显式确认候选 commit。

**代码边界：**

- `package.json`：版本、平台打包、文件关联和 GitHub publish 目标。
- `.github/workflows/build.yml`、`.github/workflows/release.yml`：质量门禁、候选构建和正式发布。
- `scripts/verify-ci-config.mjs`：发行配置和材料的静态门禁。
- `src/main/updater/`：更新检查、下载和退出安装策略。

**失败分支：** 仓库/发布目标不一致、安装器不可执行、文件关联失败、升级后设置或用户文件丢失、卸载误删知识库、未签名平台被错误宣传为正式支持。

**当前状态：** 工作流结构已配置；Git `origin` 为 Gitee，另有 `github` 远端；发布目标是 GitHub；Windows 安装/升级/卸载循环未验证。

### 3.2 首次启动与边界理解

**用户目标：** 不需要开发者讲解，理解如何打开资料、写作、引用、保存和交付。

**产品行为：** 首次启动显示合成示例任务，不写入用户知识库；关闭全部标签后显示开始页；帮助内容使用真实菜单名和能力边界。

**代码边界：**

- `src/shared/product/getting-started.ts`：应用内入门正文的单一来源。
- `src/renderer/src/data/demo-files.ts`：合成示例资料。
- `src/renderer/src/components/StartScreen/`、`HelpDialog/`：首次任务和帮助入口。
- `docs/getting-started.md`：与应用内正文的往返验证副本。

**失败分支：** 示例被标为未保存、示例写入真实库、菜单名失真、用户无法找到打开文件夹或搜索入口。

**验收信号：** 目标用户在 15 分钟内独立完成核心任务；求助、绕路和放弃均记录。

### 3.3 打开文件与知识库

**用户目标：** 直接使用已有 Markdown，不迁移、不复制、不改变目录结构。

**产品行为：** 文件夹成为持续可见的工作区；直接打开的外部 Markdown 使用同一套标签、保存和编辑体验；系统文件关联按窗口策略打开；只读检查不改原文件。

**代码边界：**

- `src/main/ipc/workspace-handlers.ts`、`file-handlers.ts`：打开、创建、移动、重命名和删除。
- `src/main/window/system-file-open.ts`：系统文件关联和多窗口分流。
- `src/main/trusted-paths.ts`、`workspace-scope.ts`：真实路径和窗口工作区授权。
- `src/renderer/src/app/workspace/`、`document-session/`：工作区和文档会话。

**失败分支：** 无权限、路径越界、符号链接换靶、编码不可识别、文件不存在、扫描被预算截断。

**验收信号：** 打开前后未编辑文件 hash 不变；覆盖范围和跳过原因可见；安装态文件关联通过。

### 3.4 找到资料

**用户目标：** 在项目资料中快速找到相关文件、标题和片段，并知道结果是否完整。

**产品行为：** 文件树、快速打开、全文搜索、标签、Wiki 链接、反链和图谱共享同一工作区上下文。普通查询优先文件名和标题；搜索可取消，旧请求不能覆盖新请求。

**代码边界：**

- `src/main/indexing/`：文件发现、增量索引、监听和缓存。
- `src/main/ipc/workspace-search-handler.ts`：全文搜索、取消、覆盖信息和 200 条命中上限。
- `src/renderer/src/components/WorkspaceSearchDialog/`：查询、结果和来源插入入口。
- `src/shared/workspace-index.ts`、`workspace-coverage.ts`：跨进程索引与覆盖契约。

**失败分支：** 5000 文件性能超时、索引未完成、单文件超限、读取失败、正则超时、查询被后续请求取消。

**当前状态：** 功能和取消契约已存在；2026-09-22 的 5000 文件性能门禁失败，是当前第一代码优先级。

### 3.5 插入来源并写作

**用户目标：** 把找到的依据写进当前文档，同时保留来源位置和撤销能力。

**产品行为：** 搜索和反链可以插入最多 8 行片段、普通 Markdown 来源链接和标题锚点；插入目标必须仍是打开搜索时的文档；来源文件不被修改。

**代码边界：**

- `src/renderer/src/lib/source-citation.ts`、`insert-citation.ts`：引用文本和目标保护。
- `src/renderer/src/components/Editor/`：Milkdown/ProseMirror 正文状态源。
- `src/renderer/src/app/AppComposition.tsx`：搜索、编辑器和来源快照编排。
- `src/shared/workspace-state.ts`：来源 mtime 快照和工作区私有状态。

**失败分支：** 搜索期间切换文档、来源不在同一盘符、标题锚点为空、编辑器未就绪、组合输入中快捷键误触发。

**验收信号：** 插入可撤销；保存重开后 Markdown 链接仍可读；来源正文 hash 不变。

### 3.6 保存、关闭与恢复

**用户目标：** 相信应用不会静默覆盖外部修改，也不会把失败操作显示为成功。

**产品行为：** 保存带 `expectedMtime` 和已知内容状态；冲突与编码损失要求明确选择；已有文件写入保留恢复材料；关闭标签/窗口前复核 dirty 和在途保存。

**代码边界：**

- `src/main/ipc/file-io.ts`、`file-write-recovery.ts`、`save-lock.ts`：写入、冲突和恢复协议。
- `src/renderer/src/app/document-session/`：快照、保存队列、回执和关闭计划。
- `src/main/history/`：版本快照。
- `src/shared/draft-storage.ts`、Main settings store：草稿与会话。

**失败分支：** 外部修改、磁盘满、权限拒绝、进程终止、编码损失、保存等待中切换会话、恢复再次中断。

**验收信号：** 上一个确认版本仍存在或可恢复；未落盘的新编辑保持 dirty；失败不会移动或删除用户原文件。

### 3.7 检查与持续维护

**用户目标：** 知道链接、附件、脚注、来源和索引是否健康，并定位需要处理的内容。

**产品行为：** 质量面板展示诊断、中文排版问题和来源状态；索引不完整时只显示“未验证”；来源缺失提供重新定位和搜索，不猜测新路径、不自动改正文。

**当前限制：** 来源时间记录由工作区共用，最多 50 条；同路径重复登记覆盖基线，并非当前文章独立引用表。“重新定位”只打开搜索。目标/附件独立变化后的索引更新、来源异步隔离和逐篇复核按 P0-07/P1-06/07 实施；这些场景尚不能写为全部通过。

**代码边界：**

- `src/main/indexing/document-index-parser.ts`：结构与诊断抽取。
- `src/renderer/src/lib/diagnostics.ts`、`source-health.ts`：纯规则。
- `src/renderer/src/components/QualityPanel/`：状态展示与用户动作。

**失败分支：** 同名文件误匹配、来源移动、mtime 变化但内容未变、索引被截断、自动修复破坏撤销历史。

**验收信号：** 检查前后正文 hash 不变；每条提示能定位或解释；自动修复仅作用于明确支持的当前文档问题。

### 3.8 导出与交付

**用户目标：** 把文档交给浏览器、Word、PDF、Pandoc 或现有团队知识平台的接收方。

**产品行为：** 导出前阻断不安全链接和空图片，确认缺失目标，提醒未完成任务；取消不写文件；HTML 资源包包含资源和脱敏交付报告；发布配置可复用。

**代码边界：**

- `src/renderer/src/hooks/exports/`、`lib/export-*`：预检、转换和导出会话。
- `src/main/ipc/export-handlers.ts`、`export-docx.ts`：目标校验和写出。
- `src/shared/publish-profile.ts`、`delivery-report.ts`：发布配置和报告 DTO。
- `src/renderer/src/components/PublishDialog/`：范围、模板和配置。

**失败分支：** 取消、缺附件、路径越界、报告超限、写入中断、接收方字体/打印/格式不兼容。

**验收信号：** 原 Markdown hash 不变；产物在目标接收软件可读；报告不含正文、绝对路径或搜索词。

### 3.9 再次打开与更新

**用户目标：** 回到上次工作位置，继续维护，而不是重新建立上下文。

**产品行为：** 恢复标签、活动文档、阅读位置、工作区布局、最近引用和搜索词；外部变化重新检查；更新可关闭且不影响本地核心任务。

**代码边界：**

- `src/main/settings/`：应用设置、工作区状态和安全凭据。
- `src/renderer/src/app/useSessionPersistReady.ts`、`document-session/`：恢复顺序和会话保护。
- `src/main/updater/`：联网与更新策略。

**失败分支：** 状态文件损坏、旧 schema、工作区已移动、自动更新失败、退出时安装与用户设置不一致。

**验收信号：** 状态损坏只回退相应部分；用户正文不受影响；关闭更新后下次启动不检查、下载或退出安装。

### 3.10 反馈与支持

**用户目标：** 在不泄露项目资料的前提下报告问题并获得可执行回复。

**产品行为：** Issue 模板只要求版本、平台、错误码和脱敏步骤；数据安全问题区分是否可恢复；后续诊断包只允许白名单环境字段。

**代码边界：**

- `.github/ISSUE_TEMPLATE/`：问题分类与隐私提醒。
- `SECURITY.md`、`PRIVACY.md`：响应渠道和数据边界。
- 后续支持摘要实现必须位于 Shared DTO + Main 采集 + Renderer 显式导出边界内。

**失败分支：** 日志包含绝对路径/正文/token、自动上传、诊断包无法由用户预览、支持流程要求用户公开敏感资料。

## 4. 优先级

### 4.1 待补齐的已有功能契约

以下是 `7c3dd53` 审阅后确定的实施目标，尚未全部实现；现有来源健康是工作区快照初版，不能视为已经逐篇跟踪。证据见[代码与功能完整性审阅](development/reviews/2026-09-22-code-function-review.md)。

- 插入与登记：只在实际插入成功后登记；异步返回属于发起它的工作区生命周期，切库、清除和卸载使旧请求失效；元数据失败不回滚已插入正文（P1-06）。
- 持续维护：每篇文章保留自己的来源基线，区分当前文章与工作区汇总；复核、最近导航清理和关系删除是不同动作；旧数据归属未知，mtime 相同不等于已经复核（P1-07）。
- 索引新鲜度：引用文章不变时，目标文件/附件变化也要更新解析与诊断；未核验、预算不足和取消不能呈现为“全部健康”（P0-07、P0-02）。
- 重新打开：旧队列/缓存写入不能更新新生命周期；缓存有界且经过 schema 校验，失败可重建，多窗口同根共享与释放明确（P1-08）。

### 4.2 产品执行顺序

本节描述产品结果，精确依赖以主实施计划为准：先 P0，再通过补充正确性门禁和种子最大阻塞后进入 P1-05 发现轮；12 人确认由 P2-05 承接，两批留存统一为 W2/W4。发现轮成功是 P1 退出条件，不能反过来作为发现轮前置。

| 顺序 | 产品结果 | 当前判断 |
| ---: | --- | --- |
| 1 | 5000 文件库仍能在预算内完成搜索 | 当前红灯，先处理代码与测量 |
| 2 | Windows 候选能安装、升级、关联、卸载且不影响用户文件 | 未验证，阻断外部 Alpha |
| 3 | GitHub/Gitee 主仓与发布目标一致，候选 Draft 真实运行 | 未验证，阻断 GitHub 发布 |
| 4 | 两位现有用户独立完成核心任务 | 未验证，决定下一项产品改动 |
| 5 | 外部用户能打开常见来源资料并交付成果 | Alpha 阶段验证 |
| 6 | 个人用户重复使用并为专业结果付费 | Beta/Pro 阶段验证 |
| 7 | 小团队重复使用交付桥梁 | 满足 3 个团队进入条件后启动 |
| 8 | 企业身份、权限、审计和部署 | 有预算与专门维护能力后独立立项 |

任何低优先级功能不得绕过前面的退出条件插队进入主线。
