## 结论与处理顺序

近期重点是让“找到资料 → 插入来源 → 持续维护 → 交付”在切换、外部修改和重启后仍可信。已有行为的缺陷修复可以立即进入失败测试，不必等待用户研究达到新增功能的门槛；批量重定位、自动改链接和团队能力仍遵守原进入条件。

## 证据与最小失败场景

### C01：来源记录必须归属于发起它的工作区生命周期

- 证据：[异步来源记录](../../../src/renderer/src/lib/remember-source-snapshot.ts)、[现有测试](../../../src/renderer/src/lib/remember-source-snapshot.test.ts)、[搜索插入入口](../../../src/renderer/src/app/AppDialogs.tsx)、[反链入口](../../../src/renderer/src/app/AppWorkspace.tsx)。现有 helper 测试只覆盖重定位搜索词。
- 挂起 A 的 `document.stat`，切到 B 后返回；断言 B 的内存设置和持久化请求不含 A 的来源。同样覆盖 A → B → A、清除来源后旧回包、卸载和 Promise reject。
- 反链入口当前在 `insertCitationFromPanel` 返回后无条件调用 `onSourceInserted`；该函数可能因编辑器未就绪提前返回。增加“插入失败不登记来源”的契约测试，登记依据须是实际插入结果。
- 来源快照失败应可解释，但不能撤销已经成功插入的正文或改变 dirty。

### C02：来源健康需要文档归属和明确的基线更新动作

- 证据：[SourceSnapshot 与去重规则](../../../src/shared/workspace-state.ts)、[来源健康计算](../../../src/renderer/src/lib/source-health.ts)、[面板装配](../../../src/renderer/src/app/AppWorkspace.tsx)。当前模型是工作区最近来源表，不是逐篇文档的引用关系表。
- A 引用 S@10，S 变为 20，B 引用 S@20：A 仍应提示变化，B 显示基线一致。B 的插入不能确认 A 已复核。
- 旧快照没有引用文档身份，迁移不得猜测归属或给每篇文档复制“已核验”状态。先保留为明确标注的旧工作区记录，再让用户对当前文档重新确认。
- mtime 一致只表示“与记录的修改时间一致”，不能证明正文一致、内容正确或用户已经复核。清除最近搜索也不应隐式删除持久来源关系；删除持久关系需要单独、可解释的动作。

### C03：引用目标变化也要使派生关系失效

- 证据：[增量索引](../../../src/main/indexing/workspace-index-service.ts)、[文件监听](../../../src/main/indexing/workspace-file-watcher.ts)、[现有增量测试](../../../src/main/indexing/workspace-index-service.test.ts)。现有测试强调未变化文件对象复用，没有覆盖目标独立变化。
- A 链接 B 和图片 P，保持 A 正文、mtime、size 不变，分别删除/补回 B、删除/补回 P、移动目标目录；刷新后关系解析、反链和缺图诊断必须反映当前目标。
- 拆开“正文解析可复用”和“目标存在性可复用”：重新检查目标不能强制重读所有正文，也不能直接信任旧 `resolvedPath`。
- watcher 接收相关附件变化时去抖、限制积压；只重验工作区内受影响依赖。无名/目录事件可受控重扫，不能开放越界资源访问。

### C04：可丢弃缓存也需要受控生命周期

- 证据：[refresh/dispose/cache 实现](../../../src/main/indexing/workspace-index-service.ts)。现有 dispose 测试只覆盖一次已完成刷新后 `load` 返回 `null`，没有待执行队列、异步缓存写或损坏 DTO。
- 挂起刷新 R1，排入 R2，dispose 后重新打开同根；放行 R1/R2，旧代次不能向新订阅发布、覆盖新缓存或恢复正文语料。
- 覆盖缓存根不匹配、未知 schema、畸形嵌套字段、中文 UTF-8 超预算、截断 JSON，以及 save/clear 交错。缓存无效时回退重建，不崩溃、不授予路径信任。
- 在读取前检查文件大小，读取过程也限制实际字节；校验后才交给消费者。磁盘持久化按根串行或使用等价代次隔离，dispose 后禁止旧代次重新写回。
