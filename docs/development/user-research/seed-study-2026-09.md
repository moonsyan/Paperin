> **类别：** 用户研究协议，不是产品功能或已完成结果。合成示例仅作练习；正式六次记录使用真实任务的可恢复副本。真实资料库路径与正文不入库。
> **参与者：** 项目开发者、开发者朋友各一人；下文只使用“参与者 A（开发者）”“参与者 B（朋友）”，不记录姓名、联系方式或可识别资料。

## 协议范围

- **目标：** 用同一任务语言记录两位现有用户的真实使用，为外部 Alpha 发现轮建立基线；不推断留存率或市场优势。
- **核心任务：** 打开资料 → 找到并插入来源 → 写一段技术说明 → 保存重开 → 导出或交付检查。
- **观察窗：** 连续两周，每人至少 3 次独立真实任务会话。截至 2026-09-22，尚未开始有效观察填写。
- **禁止：** 虚构访谈引语、路径、耗时或完成率；把礼貌反馈当作采用理由；把“两人中一人回来”报告为 50% 留存。

## 观察问题

每次只问与真实任务有关的问题：

1. 最终要交付或继续维护的成果是什么？
2. 原本会用什么工具，为什么？
3. 从哪里找到资料，是否把来源带进当前文档？
4. 哪一步需要解释、绕路或失败？
5. 保存、重开和接收方检查是否正确？
6. 下一次是否会主动继续使用，具体用于什么任务？

## 当前工程风险提示

下列内容来自 [PROJECT-STATUS](../../PROJECT-STATUS.md)，只用于主持人判断任务是否被工程红灯干扰，不代表参与者已经遇到这些问题：

- 当前 Electron smoke 已通过核心任务链路，但自动化不能替代真人发现能力和安装态验证。
- 2026-09-22 的 5000 篇合成索引/搜索及生产搜索门禁失败，真实大库任务必须记录库规模与等待，不从历史单次结果外推。
- Windows 安装、升级、卸载、文件关联和用户文件保留尚无完整候选证据。
- 真实中文输入法、九主题缩放、多窗口重启和复杂导出接收方矩阵仍未完成。

引用插入与技术文章/决策记录模板属于已有工程能力，见 [command-panels](../../command-panels.md) 和 [compatibility-matrix](../../compatibility-matrix.md)；只有真实会话记录才能证明用户能发现并使用它们。

## 结项条件

参与者 A 为开发者，不能计入 U01 的陌生首次用户样本；本轮也不能直接并入 Alpha/Beta 的成功率分母。失访与退出按协议分别处理，撤回删除请求不影响产品使用。

每人 3 次记录完整后，按人归纳最大阻塞、成果是否实际使用和再次使用理由。任何汇总必须保留失败、求助和放弃样本。完成本基线不自动允许公开发布；外部 Alpha 还依赖 P0 发行门禁，详见[产品工作流实施计划](../../superpowers/plans/2026-09-22-product-workflow-implementation.md)。
