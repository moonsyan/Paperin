# R12：两位现有用户任务基线（2026-09）

> **类别：** 用户研究文档，不是产品功能。操作在合成示例或可恢复副本上进行；真实资料库路径与正文不入库。  
> **已知参与者（仅协议层）：** 项目开发者、开发者朋友各一人；下文以「参与者 A（开发者）」「参与者 B（朋友）」匿名指代，不记录姓名、联系方式或可识别资料。

## 1. 协议范围

- **目标：** 为后续 R13–R14 对照建立同一任务语言下的逐人、逐次任务记录；不推断留存率或产品优势。
- **核心任务表述（与 R11 一致）：** 打开资料 → 用来源写一段技术说明 → 保存重开 → 导出或交付检查。
- **观察窗：** 计划两周；每人至少记录 **三次** 独立任务会话（见下表）。截至文档建立日，**尚未开始有效观察填写**。
- **禁止：** 虚构访谈引语、路径、耗时、完成率；把礼貌反馈当作采用理由；合并两人样本报「留存成功」。

## 5. 工程问题与任务风险的对照（R01–R11）

下列条目来自 [R00–R17 实施任务](../../superpowers/plans/2026-09-20-product-strategy-execution.md) 与 [REFACTOR-STATUS](../../REFACTOR-STATUS.md) 的**工程结项说明**，用于标记「若未修复或未完成平台验证，可能妨碍任务基线」的类别。**不代表**参与者 A/B 已在观察中遇到这些问题。

| 任务 | 可能影响任务闭环的残留边界（工程记录） |
| --- | --- |
| R00 | 早期 smoke 曾报 React #301 等；R09 后 smoke 已通过，但部分历史记录仍标注「未重跑」场景，平台级端到端需单独证据。 |
| R01 | 损坏/不支持编码在读取阶段拒绝；用户若持有异常编码文件，打开或索引可能阻塞，需显式决策而非静默损坏。 |
| R02 | 保存绑定内容哈希；外部等长替换会 CONFLICT。任务含「保存重开」时，冲突与强制覆盖路径必须被理解。 |
| R03–R04 | 集合 HTML/资源包与单篇路径语义分表；不完整索引或内联图片失败时导出会被阻止并需反馈。 |
| R05–R06 | 超大/超深/超预算文件可能未进入搜索；目录级 rescan 与单篇 READ_ERROR 隔离，但「搜不到」与「没有结果」需 UI 区分。 |
| R07 | 多窗口草稿会话与外部改盘边界已有 Main 契约；真实双窗口长会话仍依赖人工/Electron 证据。 |
| R08 | 弹窗键盘、IME 组合态与主题对比度：自动化已覆盖部分；九主题×缩放×真机 IME 矩阵仍为 **UNVERIFIED**。 |
| R09 | M01 多结构 5 MiB、第二设备、8 小时稳定性等为 **UNVERIFIED**；大文档任务耗时不应从单次 dev 记录外推。 |
| R10 | 候选包与安装/升级循环 **未执行**（`release-validation.md`）；外部试用扩大前缺安装证据。 |
| R11 | 引用插入与模板入口已有实现与测试；**无口头提示完成演示任务**仍为未执行（见计划 §14 最后一项）。 |

引用流程（工作区搜索/反链 → 插入引用）与技术文章/决策记录模板属于**已有工程能力**（见 [command-panels](../../command-panels.md)、[compatibility-matrix](../../compatibility-matrix.md)），不在此重复宣称用户验收已通过。
