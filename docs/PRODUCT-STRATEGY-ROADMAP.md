## 1. 战略结论

**Paperin 应聚焦“已有 Markdown 资料的中文技术与知识内容作者”，成为把旧资料快速写进新成果的本地知识工作台。**

对外一句话：**打开自己的 Markdown 文件夹，找回旧资料，安心写成新文章。**

长期定位保留“个人长期知识工作”，近期切入口收窄为：经常写技术文章、教程、产品方案的人，已经积累 Markdown，不愿花大量时间配置工具，每周需要形成可以交付的内容。

用户选择 Paperin 的理由应是一条可观察的任务路径：

```text
直接打开已有目录 → 找到旧笔记中的段落 → 带来源插入当前文章
→ 继续写作且可靠保存 → 输出可读成果 → 下周继续使用这份资料
```

近期重点为“可靠保存 + 默认可用的资料复用 + 稳定交付”。研究检索、移动记录和团队协作属于有条件的相邻市场。真正的替代品还包括“继续用原工具”和“资源管理器 + 搜索 + 手动复制”；必须证明换工具值得。

## 2. 对原战略的纠正

| 原判断或遗漏 | 修正 | 对投入的影响 |
| --- | --- | --- |
| “个人研究者与长期写作者”包含过多人群 | 首批聚焦已有 Markdown、每周产出文章/方案的中文桌面用户；学术引文与 PDF 管理另行验证 | 先做一条真实任务，避免同时做文献管理与办公协作 |
| 本地文件、链接、导出被称为护城河 | 它们是基础资格，竞品已有重叠；优势要通过任务时间、正确性和留存证明 | 形成无需搭建的组合体验 |
| Notion 被简化为在线工具 | 桌面/移动已有离线页面，也能导出 Markdown/CSV | 比较源文件模型与控制权，不使用过时宣传 |
| Torria 和 Tana 被合并 | Torria 的名称/官网尚未确认，公开检索没有足以识别该产品的官方依据 | 单列待核实，不推断功能或用 Tana 代替 |
| 多种导出格式被全部描述为稳定 | 入口不等于交付；先验证 Markdown/HTML/PDF，DOCX 明确支持子集，其余说明依赖 | 提高高频输出质量，停止格式数量竞赛 |
| 阶段 0 再做 smoke、收藏和整套 UI | 路径条、抽屉和轻大纲已经在；完成度只维护一份当前记录 | 补实际缺口，不重复建设 |
| 12 个月按时间排满 AI、同步、协作 | 改为有进入条件的选项，时间到了也不自动启动 | 避免过早承担云成本和维护面 |
| 增长只有模板、社区、付费方向 | 增加筛选、招募、迁移、四周队列、渠道成本和止损 | 开发与需求验证同时进行 |
| 匿名计数、可关闭的界限不清 | 本地统计与上传分开；上传默认关闭、另行同意和预览 | 不能为留存统计削弱信任 |
| 16 分评分门槛没有清楚的范围 | 改为明确的 100 分评分、证据置信度和工程日；安全不参加商业排序 | 决策可复核 |

Torria 待确认不阻塞其余定位与实施；确认后补同一任务比较，不预设结论。

## 3. 项目实际起点

### 3.1 已有资产及其限制

| 资产 | 代码/记录依据 | 战略意义与证据边界 |
| --- | --- | --- |
| typed API 与进程边界 | [领域模型](domain-model.md)、`src/shared/`、`src/preload/` | 沿用现有技术栈；边界存在不等于安全审计完成 |
| 工作区、外部文件、多标签、保存/恢复 | `app/document-session/`、`src/main/ipc/` | 能接受已有文件；大文档末次输入与关闭仍需完整证据 |
| 中文 Markdown 编辑与扩展 | `components/Editor/`、[兼容矩阵](compatibility-matrix.md) | 写作基础广；往返兼容与真实 IME 继续验证 |
| 搜索、收藏、链接、反链、图谱 | `WorkspaceSearchDialog/`、`lib/backlinks.ts`、状态记录 | 零件存在；本次没有证据证明预览—插入—返回已完整闭环 |
| 多种输出入口与资源包 | `hooks/exports/`、`lib/export-bundle.ts` | 稳定现有路径，不另建发布系统代替验收 |
| 路径条、抽屉、轻大纲、主题样张 | REFACTOR-STATUS 的 M2 批次 | 已有实现；缩放、IME、焦点、保存语义残项继续验收 |
| 收藏恢复/取消、品牌统一 | 2026-09-13 状态记录及代码 | 保留回归，不再作为全新功能安排 |
| 三平台构建/发布 workflow | `.github/workflows/build.yml`、`release.yml` | 配置存在；不据此推断远端 CI、安装、签名、升级已通过 |

本轮工程已覆盖可恢复写入的可控注入点、保存与关闭的身份复核，以及固定长段落 5 MiB Electron 硬门禁的既有通过记录。真实输入法、三平台安装、多结构性能和用户留存仍未验证。未取得用户量、留存、收入或市场份额基线；本篇商业与体验数字均为待验证目标。

### 3.2 P0 信任问题

1. **大文档保存仍有失败基线。** 5 MiB 场景曾出现 `SAVE_RESULT_TIMEOUT`、`diskHasEdit:false`。现在性能门禁会分别记录快捷键分发、Renderer 的 `document.save` 调用与回执，仍需据此定位序列化、线程阻塞、IPC 或写盘瓶颈并通过硬门禁。
2. **快照超时与关闭误放行已修复，完整矩阵未完成。** 保存请求现在绑定目标文件和活动会话序号；超时或会话改变不写旧缓存、也不允许关闭。IME、卸载、保存中继续输入、阈值两侧和 5 MiB 的完整 Q02 组合仍待验证。
3. **可恢复写入已实现，故障证明未完成。** 已有文件写入使用同目录 journal/backup 记录，未确认中断可恢复最后确认版本；仍需完成权限、磁盘满、进程终止、符号链接、并发和三平台文件身份矩阵。[Node 复制契约](https://nodejs.org/api/fs.html#fspromisescopyfilesrc-dest-mode)

这些问题直接影响用户是否敢交付真实资料，修复先于扩大分发。当前工程闭环不等于完整故障、平台或用户验收。

## 4. 客群与切入方式

### 4.1 首批招募标准

先做 12 名用户的任务测试，再做两批各至少 20 名已激活用户的四周试用。优先满足：中文写作、桌面为主、已有约 100–5000 篇 Markdown、每周至少写成一篇文章/教程/方案、过去两周实际遇到过“找不到旧资料”或“搬进新文章费劲”。这是招募范围，不是产品容量承诺。

移动随手记为主、实时协作刚需、深度插件依赖、学术引文格式管理为主、数据库工作流为主的用户暂不优先招募。不向他们承诺近期完整替代原工具。

### 4.2 先共存，再争取成为主入口

| 原工作流 | 第一笔价值 | 试用方式与限制 |
| --- | --- | --- |
| Typora + 文件夹 | 写文章时查到并插入旧资料，保留原写作位置 | 打开目录或副本；不凭外观宣称编辑体验优于 Typora |
| Obsidian + 少量插件 | 默认就能完成查找、来源引用与交付 | 普通 Markdown 可共存；不兼容全部插件、Dataview、Bases 配置和特有语法 |
| Notion / 语雀资料 | 导出的资料成为本地写作来源 | 检查导出包和附件/链接损失；不迁移权限、评论、数据库关系或历史 |
| 思源资料 | 导出的 Markdown 用于连续文章写作 | 使用官方导出副本；不直接读写 `.sy`，不假装块 ID 无损等价 |

第一天不要求搬走整个知识库。只读试开不改正文，转换写入副本，明确保存才修改原文件；并发编辑通过冲突处理保护。第三方同步目录需按实际环境验证，不能把普通目录支持宣传为全面同步安全。

### 4.3 三项可验证承诺

| 承诺 | 证明方式 | 初始门槛摘要 |
| --- | --- | --- |
| 敢用自己的文件 | 零改写试开、故障恢复、保存/关闭矩阵 | 非编辑试开原 Markdown/附件字节不变；约定故障场景 100% 保留或恢复已确认版本 |
| 旧资料能写进新文章 | 与用户常用工具配对完成任务 | 至少 10/12 独立成功；成功者配对中位耗时改善 ≥30%，失败率不增加 |
| 写完能交付，下周仍想用 | 输出检查 + 四周队列 | 核心输出正确；两批 W4 有效留存各 ≥40%，复用留存各 ≥25% |

完整分母和失败处理见验收协议。未达标前，宣传使用目标描述，不使用已更快、更轻、更可靠的比较结论。

## 5. 竞争分析

事实于 2026-09-14 核对官方资料；机会判断是推论，没有进行全产品横向性能测试。不比较无法核实的市场份额、用户数和价格。

| 产品 | 已核实的能力与定位 | Paperin 的选择 |
| --- | --- | --- |
| Obsidian | 本地纯文本 Markdown、链接、扩展、Sync/Publish；Bases 已是基于本地文件及属性的核心能力 | 本地+双链+数据库视图并非空白。争取不愿搭建工作流的作者。[官网](https://obsidian.md/)、[Bases](https://obsidian.md/help/bases) |
| Typora | 实时预览、文件树/列表、大纲、专注/打字机模式，含 PDF 等多种导出 | 不能说它没有文件管理和交付。证明跨笔记复用更顺畅，同时保持写作连续性。[官网](https://typora.io/) |
| Notion | 桌面/移动支持离线页面，套餐影响自动下载；可导出 Markdown、CSV、HTML | 差异在于直接以本地 Markdown 为源、无账号核心任务与可检查迁移。[离线](https://www.notion.com/help/use-pages-offline)、[导出](https://www.notion.com/help/export-your-content) |
| 思源 | 隐私优先、块引用、双链、数据库、Markdown/PDF/Word/HTML 输出；原生文档为 `.sy` JSON | 本地、输出和中文都正面重叠；选择标准文件与连续文章写作，不把更轻当实测事实。[官方仓库](https://github.com/siyuan-note/siyuan) |
| 语雀 | 同时面向个人知识管理/分享与团队文档协同 | 个人用户也在其服务范围。争取本地原稿与个人写作，产物仍可交给协作平台。[官方介绍](https://www.yuque.com/about/groups) |
| Torria | 名称与官网待确认 | 保留比较席位，不与 Tana 合并，不据未知功能安排研发 |

可积累的优势包括：经过真实任务验证的默认流程；来源可追溯与写作位置恢复；合成兼容夹具和故障回归库；公开的兼容/恢复/迁出记录；围绕技术文章与方案的模板、案例和推荐网络。它们尚不是不可复制的壁垒，竞争力来自持续交付和目标用户信任。

## 6. 产品发展规则

### 6.1 原则

- Markdown 与附件是源数据；索引/缓存可重建，历史/草稿/偏好是独立元数据，不得因可重建而随意删除。
- 保存确认对应文档与版本；冲突、编码损失、取消、超时保留内容和选择。
- 知识库持续在场，外部文件沿用同一工作区/标签/保存体验，并明确搜索范围。
- 低频能力接入既有命令与面板；不以打卡、知识数量竞赛和强制提醒制造留存。
- 离线核心流程无需账号；外部工具依赖的导出先预检，不承诺未装依赖也能完成。
- 每项开发同时交付实现、测试、文档与验证，遵循 AGENTS.md，不用商业目标降低安全门禁。

### 6.2 优先级与评分

P0 是数据安全、保存/关闭正确性、安全边界和发布阻塞，立即处理。P1 是核心任务、激活、留存、发布可用性。P2 是有证据的效率/增长扩展，通过前置门禁后做。P3 是远期选项，只保留研究。

非 P0 功能每项按 0–5 分评分：客群高频任务价值权重 30，复用/交付改善 25，信任/兼容 20，激活/留存/付费证据 15，维护可控性 10。`总分 = Σ(得分 / 5 × 权重)`，范围 0–100；低于 70 不进入近期开发，超过 70 也不自动立项。

同级按 `总分 × 证据置信度 / 预计工程日` 辅助排序。置信度：想法 0.25、多次访谈 0.5、任务观察 0.75、重复队列验证 1.0；工程日最少计 1，包含测试、文档和维护成本。产品/工程负责人共同记录反证。P0 不参加增长 ROI 排名；必需的测量先做最小实验，不造复杂统计平台。

### 6.3 阶段推进

| 阶段 | 用户结果 | 重点 | 退出条件 |
| --- | --- | --- | --- |
| G0 可信试用 | 敢打开自己的资料 | 保存/关闭/恢复、性能、兼容试开、平台准备；同时访谈 | P0 清零、正确性矩阵全过、适用平台候选包可用，否则仅用合成数据测试 |
| G1 核心复用 | 旧段落进入新文章 | 预览、引用/链接插入、返回位置、中文搜索 | 12 人任务门槛和体验预算通过 |
| G2 固定使用 | 成果可交付，下周仍继续 | 核心输出、两个模板、两批四周队列、发布质量 | 输出/留存/全部承诺平台门禁通过 |
| G3 可重复增长 | 新用户来自可重复的渠道并留下 | 迁移指南、案例、作者合作、获客和商业实验 | 至少一个渠道带来可观察的 W4 留存用户，支持成本可承担 |

按一名熟悉项目的工程师，每周约 4 个有效工程日，另留用户沟通时间，实施计划约 15–22 周（含缓冲，以任务合计为准）。没有团队/预算/用户基线，不承诺日历发布日期。四周留存必须等窗口成熟，不能用开发完工日替代。

6–12 个月保留 AI 检索、同步、个人发布、邻近客群等选项；每次最多启动一个新方向，不自动把所有选项做完。

## 7. 获取固定用户与增长

### 7.1 招募与激活

每周访谈/观察 3–5 名目标用户，先问最近一次文章如何找资料、失败在哪里、如何交付，再展示产品。首批 12 人至少一半不是开发者熟人，覆盖 Typora 和 Obsidian 既有工作流。

展示 60–90 秒真实任务“把旧资料写进今天的文章”，附小示例库、兼容边界和迁出说明。允许从复制目录开始，首次编辑无需账号/插件。访谈和社群联系是后续运营任务，本次不代用户发送消息。

### 7.2 渠道与止损

| 渠道 | 实验 | 成功信号 | 调整或停止条件 |
| --- | --- | --- | --- |
| 中文技术社区/开发者社区 | 每两周一篇工作流案例，附合成示例与限制 | 合格激活和成熟 W4 留存 | 两轮只有浏览量没有激活，调整受众/表达 |
| 搜索型教程 | Markdown 查找引用、Typora/Obsidian 共存试用指南 | 有任务意图的用户按指南完成试用 | 迁移失败/误解多，先修兼容与引导 |
| 3–5 位作者合作 | 用作者真实任务展示，说明试用关系 | 案例中的收益可以被新用户复现 | 不购买好评，不把曝光算留存 |
| 用户自主推荐 | 分享普通模板/示例/成果，品牌署名可选 | 被推荐者成为有效使用者 | 不做强制水印、邀请码和社交解锁 |

G2 之前不规模投放。G3 每轮可先设 20 小时运营投入、最多人民币 2,000 元现金上限，**是建议预算，不构成支出授权**。渠道分别记录可归因到达、激活、成熟 W4、时长和成本；无法归因写未知，不推测来源。

### 7.3 用户规模阶梯

- 0→20：验证价值、发现任务阻塞，可投入较多人工支持，不以收入为目标。
- 20→100：两批四周留存可重复，兼容/引导稳定，建立每周问题复盘。
- 100→500：至少一个渠道反复带来留存用户，支持成本可承担才加预算。
- 500 之后：依据真实留存、收入、资源决定扩客群/平台，不承诺某月达到某人数。

固定用户定义为激活后第 4 周仍有效编辑/复用并说明持续任务。北极星为“每周完成有效资料复用的研究样本用户数”；自愿样本不能外推为全量用户规模。完整定义见验收协议。

## 8. 商业可持续性

`package.json` 标记 MIT；收费前核对实际许可证与第三方义务，不假设能收回既有授权或把现有免费能力关掉。核心编辑、标准文件使用、恢复与迁出保留为信任底座。

优先验证专业交付价值：批量输出、可复用品牌模板、交付检查、维护支持。AI/云服务需要独立成本和隐私证据；企业权限不是近期营收主线。

步骤：访谈至少 15 名完成核心任务的用户 → 提供真实交付样例 → 对比一次性购买/年度维护两种报价表达 → 经产品负责人决定后开展实际付费小实验。愿付问卷不等于收入；至少 5 名非关联用户真实付费并观察 30 天退款/支持成本，才继续产品化。无支付能力时记录商业未验证。

贡献毛利 = 实收收入减退款、支付手续费、直接服务成本与支持工时成本。获客成本分别报告现金/人力；扩大付费获客前要求贡献毛利为正、预计回收期 ≤6 个月。样本不足不估无限期 LTV，不以未验证订阅收入支撑长期云成本。两轮报价仍无真实付费信号，暂停收费功能扩建，复核交付价值或选择免费开源维护路线。

## 9. 指标与战略反证

数字是本项目初始决策门槛，不是行业基准；冻结定义后采样，不事后改分母。

| 指标 | 初始门槛 | 未达标时决策 |
| --- | --- | --- |
| 首次五分钟激活 | 12 人中至少 10 人独立完成打开、编辑、保存、再次找到 | 修引导、权限与状态反馈 |
| 复用任务 | 至少 10/12 成功；配对中位耗时降低 ≥30%，失败率不增加 | 最多两轮聚焦改进搜索/插入/往返 |
| 真实成果 | 每批 ≥50% 已激活用户在首 14 天完成一次有用成果 | 修输出或客群匹配，不加格式按钮充数 |
| W4 有效留存 | 两批各 n≥20 已激活用户，分别 ≥40% | 分析流失，不扩大投放 |
| W4 复用留存 | 两批分别 ≥25% 已激活用户在第 4 周完成有效复用 | 编辑留存高而复用低时，重新考虑文件写作定位 |
| 文件信任 | 无未解决的已确认丢失/静默覆盖问题，约定故障矩阵全过 | 阻断分发/获客，先恢复用户资料与修复 |
| 支持负担 | 100 名可观察 WAU 后连续 4 周，新增核心阻塞工单 ≤5/100 WAU，支持 ≤4 小时/周 | 暂缓加速，修可靠性和自助说明 |

两轮改进仍无效率提升时，不继续宣称复用优势成立；复核客群、任务频率和一体化是否必要。主要流失若来自跨设备且可靠性达标，可提前研究同步；若来自编辑基本功，就继续修编辑。

远期选项进入条件：

- AI：至少 10 名留存用户反复遇到关键词检索无法完成的任务；同题集小实验成功率提高 ≥15 个百分点；来源可核验、发送范围可见、无 AI 仍完整可用。
- 同步：至少 30 名流失/留存访谈者中 ≥30% 将跨设备列为主要阻碍，至少 10 名愿参与验证；先验证冲突/恢复再决定服务形态。
- 静态发布：至少 10 名留存用户连续两周重复分享且现有资源包明确不足；先做可自行托管产物。
- 团队、移动和插件生态：另写客群、资源、安全和商业论证，不能沿用个人桌面留存作为成立证据。

## 10. 执行治理与完成定义

每两周一个主要用户结果；高风险状态变更在制品最多一个。产品负责人负责画像、证据和取舍；工程负责人负责架构、正确性和性能；验证负责人负责用户任务及平台验收。角色可兼任，但自己的演示不能当独立用户研究。

每周看 P0/任务阻塞/支持，每两周看任务成功率，每个成熟队列看 W4，每季度复核市场选择与商业模式。完成度只在 REFACTOR-STATUS 维护，记录 commit、环境、失败与缺证据项；历史通过不能覆盖后续失败。

战略优势首轮成立要求 G0–G2 全过：文件可信、复用效率改善、成果可交付、两批留存成立、全部承诺平台发布门禁通过。G3 再证明可重复增长；收入另以真实支付验证。文档完成、代码合并、下载量增长都不等于这些条件已满足。
